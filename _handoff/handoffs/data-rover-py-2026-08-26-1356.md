# Handoff: Inline (non-ref) transform snippets for table/exporter JSON export

## Mission
Let the export `transform(doc)` hook be authored **inline** as well as by artifact
reference, mirroring how table script columns / nav script steps already use
`SnippetSource` (`{ref?, definition?}`). Today `ExporterEntry.transform` and
`TableDefinition.transform` are `TableRef | None` — ref-only by an explicit past
decision the user now wants reversed. Project: `/home/mdp/workspace/data-rover-py`.
Done = both surfaces accept a ref OR inline code, old payloads load unchanged,
strict export-time validation preserved, tests + `pixi run dr-tidy` green, docs corrected.

Status: design was brainstormed, presented in chat, then REVIEWED a second time against
the real seams (2026-08-26, second pass). That review found three defects the first design
would have introduced, and three decisions have since been ratified by the user
(bounded `TransformHost` sessions, add/remove UI affordance, accept the viewer-execution
surface). The **Plan** below is the corrected one. **The user has NOT yet approved
implementation.** Get approval before writing code.

## Standing Constraints
- **Replace the field type, do not add a parallel one.** `ExporterEntry.transform` and
  `TableDefinition.transform` both become `SnippetSource | None`. A parallel
  `transform_code: str | None` beside `TableRef` was considered and rejected — it means
  hand-maintaining mutual exclusion that `SnippetSource`'s validator already enforces, and
  the bundle walk already understands the `SnippetSource` shape.
- **No migration.** `SnippetSource` parses `{"ref": "..."}` identically to `TableRef`, so
  every stored exporter/table payload loads unchanged. Do not bump `schema_version`.
- **`{}` means no transform, tolerantly — and that is a GATE change, not just a resolver
  one.** `null` stays the canonical "none" the UI writes, but an unconfigured `{}` must not
  422. Both surfaces currently gate on `is not None`, which `{}` satisfies — see Plan step 2
  (server) and step 7 (client). Every gate becomes `t is not None and not t.is_empty`.
- **Strictness stays where it is: at export time, never at Save.** A missing/foreign/
  non-`code_snippet` ref, or inline code without a one-arg top-level `transform(doc)`, is a
  `ValueError` → 422 naming the entry. Never a silent skip — shipping untransformed data at
  200 is the failure mode this whole hook is strict about (`routes/tables.py:135` docstring).
- **Re-derive the entry point from the code, never trust stored `entry_points`.** Applies to
  inline exactly as it does to refs; stored `entry_points` is advisory metadata.
- **`TransformHost` gains exactly ONE bounded change** (ratified 2026-08-26, reversing the
  earlier "do not touch" for this detail only): `self._sessions` gets a small LRU cap so a
  run cannot hold 50 live guest instances at once. Its code-string keying stays — an inline
  snippet and a ref with identical code still share one warm session — and the interactive
  slot accounting is untouched. Rationale: ref mode made SHARING the common case (a handful
  of snippets across 50 entries); inline makes DISTINCT code the common case, against
  `snippet_pool_size` = 6 and a 256 MiB per-store cap.
- **`disabled` must reach the inline editor.** `TransformPicker` takes `disabled`;
  `SnippetSourceEditor` does not. `ExporterTab` passes `disabled={disabledEntry}`
  (`!editable || locked` — viewer, not checked out, or peer-locked), and the Export button
  ships dirty drafts inline, so losing that gate lets a viewer author and execute code.
  Adding the prop to the shared component is in scope.
- **Manifest must stay wall-clock-free and deterministic** (`build_manifest`'s byte-identical
  -zips-at-the-same-rev guarantee). For inline, record `inline:<sha256(code)[:12]>` on
  `ManifestEntry.transform` — recording `None` would be indistinguishable from "no transform".
  Artifact ids are uuids, so the prefix cannot collide; the field's docstring must state the
  new two-form grammar, since a consumer resolving it as an artifact id needs to know.
- **The viewer-callable inline-execution surface is ACCEPTED, not overlooked** (ratified
  2026-08-26). `EvaluateTableIn.definition` and `RunExportIn.definition` are both
  viewer-callable, so inline transform lets a viewer execute arbitrary sandboxed code via
  `/tables/export` and `/exports/run`. This is NOT an escalation — viewers already run
  arbitrary inline code through `POST /snippets/run` — but the export path draws a GLOBAL
  interactive slot with no `snippet_per_user_concurrency` cap. Bounded by
  `snippet_eval_budget_s` (30 s, shared per run) and `snippet_concurrency` (4). Document the
  conclusion and pin it with a test; do NOT add a per-user cap.
- **UI placement (user's explicit choice):** the inline editor renders **collapsed under the
  exporter entry row**, via `SnippetSourceEditor`'s existing chevron/`collapseKey` disclosure —
  the same interaction table script columns use. NOT inside the per-entry `EntryLayoutDialog`.
- **UI control shape (ratified 2026-08-26):** the wrapper contributes ONLY the nullable edge —
  an "Add transform" affordance when `transform == null`, and an × that writes `null`. Mode
  (saved ↔ inline) stays entirely inside `SnippetSourceEditor`'s existing toggle. A
  `none | saved | inline` three-way select was rejected: it puts two mode controls on screen.
- **Classification: bounded** (brainstorming skill). The ref/inline flow already exists in
  this repo, so: short design in chat, no spec file, no plan document. TDD applies.
- **Scope covers both surfaces** (`ExporterEntry.transform` AND `TableDefinition.transform`).
  Decided by the assistant, not asked: they share the picker and the resolver, and leaving
  one ref-only would fork both. The no-bleed rule is unaffected — an exporter entry still
  never inherits a table's own transform (`entryForTable` sets `transform: null`).
- **`transform` remains excluded from console runs.** `RunRequest.entry` is
  `script|value|step`; there is no document to bind a console run against. `ConsoleEntry`
  keeps carving it out; only `SnippetSourceEditor`'s `entry` prop widens to `BoundEntry`.

## Verified Non-Issues — do not re-litigate
Each was checked against the code during the review pass:
- `extract_refs`/`rewrite_refs` need NO change. The walk matches on `key == "ref" and
  isinstance(value, str)`, so a `SnippetSource` with `ref: None` contributes nothing and an
  inline `definition` subtree (code/language/entry_points) is walked harmlessly.
- `core/table/resolve.py::resolve_table_refs` is field-EXPLICIT (row source navigation +
  columns only). Retyping `transform` does not drag it into snippet inlining, and
  `table_has_script` correctly stays blind to it.
- `routes/exports.py`'s HOST gate is already `any(c is not None for c in transform_codes)`,
  so it handles `{}` → `None` correctly. Only the per-entry FORMAT check needs fixing.
- `ExporterTab`'s reorder (`createColumnDrag`, geometry mode) snapshots real element rects,
  so a taller row with an expanded editor does not break the offset math — provided the
  editor sits INSIDE the `data-export-entry-drop` element.
- `derive_entry_points` swallows `SyntaxError` and returns `[]` (`core/script/lint.py:59`),
  so unparseable inline code cannot 500 the export route.
- `core/script/README.md` is already ref/inline-agnostic. No doc change needed there.
- Bundle export of an inline-transform exporter becomes SELF-CONTAINED (no snippet dep) —
  a genuine improvement over ref mode, worth a test rather than a worry.

## Deferred — Do Not Do
- **A per-entry `EntryLayoutDialog` home for the transform editor** — the user picked the
  collapsed-under-the-row option instead. Do not "improve" it back into the dialog.
- **A `none | saved | inline` three-way select** — rejected in the review; see Standing
  Constraints for the add/remove shape that replaced it.
- **A separate `transform_code` field alongside `TableRef`** — rejected by the assistant in
  the design; see Standing Constraints for why.
- **Any change to the sandbox, or to concurrency ACCOUNTING** — the LRU bound on
  `TransformHost._sessions` (Plan step 4) is the ONE ratified exception. No per-user cap on
  `open_transform_host`, no change to how slots are drawn or released.
- **Allowing `transform` on `xlsx`/`csv`** — unchanged 422; silently skipping a transform on
  a non-JSON format is a functional-contract hole, not a presentation preference.
- **A console Test panel for `transform`** — no `transform` entry exists in `RunRequest`, and
  no document exists to bind it to. Render the panel only for `ConsoleEntry`.

## Plan

0. **Verify one thing before writing UI.** Confirm which path `Table/ExportDialog.svelte`'s
   Export takes — `EvaluateTableIn` accepts an inline `definition`, so if the dialog ships
   the staged draft, an inline transform takes effect immediately; if it ships `artifact_id`,
   the code only applies after a commit and the dialog needs a "commit to apply" hint. The
   confusion is much sharper for typed code than it was for a ref picker.
1. **Core schema.** `ExporterEntry.transform` (`core/table/exporter.py:105`) and
   `TableDefinition.transform` (`core/table/schema.py:309`) → `SnippetSource | None`.
   Update both docstrings (they currently assert ref-only). `TableRef` itself stays — it is
   still used for `ExporterEntry.source` etc., and its own docstring (`schema.py:184`) about
   the literal `"ref"` key remains true.
2. **Server resolver AND its two gates.** `_resolve_transform_code(db, project_id, ref, name)`
   → `_resolve_transform_source(db, project_id, src, name) -> str | None`: empty/None →
   `None`; `definition` → its `code`, with the same strict `derive_entry_points` re-check and
   no DB hit; `ref` → today's path verbatim. Then fix the CALL SITES, which is where the
   first design was wrong:
   - `routes/tables.py:555` — `if defn.transform is not None:` currently guards BOTH the
     `format not in JSON_FAMILY` 422 AND `open_transform_host`. Under `SnippetSource` a `{}`
     source would 422 an xlsx export and take a concurrency slot on a json one. Becomes
     `is not None and not .is_empty`.
   - `routes/exports.py:276` — same `is not None` around the per-entry format check; same fix.
     (Its host gate is already correct — see Verified Non-Issues.)
   - **Message shape.** Today's text interpolates the ref
     (`f"{name}: snippet {ref} does not define …"`), which inline has none of. Give inline
     its own wording, and split out the syntax-error case — `derive_entry_points` returns `[]`
     for unparseable code, so the most common inline mistake would otherwise land on a
     misleading "does not define a one-argument top-level transform(doc)". Decide the exact
     strings BEFORE writing tests; the tests will pin them.
3. **Manifest.** `ManifestEntry.transform` records `entry.transform.ref` for a ref and
   `inline:<sha256(code)[:12]>` for inline; update its docstring to state the two-form
   grammar and why the prefix cannot collide (`api/export_manifest.py` + the write site
   `routes/exports.py:481`).
4. **Bound `TransformHost._sessions`.** Small LRU cap (start at 8; the number is a constant,
   not a setting) — closing the least-recently-used `SnippetSession` past it. Keying by code
   string, slot accounting, and `close()`'s `finally: release_global()` all stay exactly as
   they are. Test: an export with many distinct inline transforms never holds more than the
   cap, and still produces correct per-entry output.
5. **Bundles.** No code change expected — verify with a test that a ref-mode transform is
   still picked up by `extract_refs` and an inline one contributes no dep.
6. **Frontend shared component (`SnippetSourceEditor`).** Widen `entry` from `ConsoleEntry`
   to `BoundEntry`; mount `SnippetTestPanel` only when `entry !== 'transform'`; **add a

   editability. Everything else there is already parameterized by `entry` (ref filter,

7. **Frontend wrapper.** Delete `TransformPicker.svelte`; add a thin `TransformSourceEditor`
