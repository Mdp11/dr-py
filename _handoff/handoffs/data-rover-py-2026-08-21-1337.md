## Standing Constraints
- **Everything through pixi.** Frontend pixi tasks set `cwd=frontend` internally — run `pixi run frontend-test` from the repo root (a bare `pixi run -e frontend npm test` fails).
- **`pixi run dr-tidy` MUTATES by default** (`ruff format` / `prettier --write`, no `--check`), so exit 0 is NOT proof the tree is format-clean. After running it, check `git status --short`. `pixi run dr-tidy check_only=true` is the gate that actually fails on drift — use it in the plan's verification step. (Phase 3 shipped four format-drifted files past a "green" dr-tidy because of exactly this.)
- **Run `pixi run core-lint` before every Python commit** — pytest cannot catch an annotation-only break under `from __future__ import annotations`.
- **Comments/docstrings are contract here** — comment accuracy is merge-blocking, and has been for three phases running. Dense "why the invariant exists" style.
- **Never block Save** — every strictness rule is enforced at run time (422/404/409 naming the offender), never at Save. Phase 3 *removed* the last Save gate (F-16); do not add one.
- **RENDER ONLY boundary** — export presentation must never touch evaluation: cell values, row order and script cache keys stay computed off the ORIGINAL table definition. §8 says the same for `transform` (it runs after rendering, so cache keys are unaffected).
- **The no-bleed rule (§8)** — a table's own `transform` applies only to its standalone export; an exporter entry applies only its entry-level `transform`; entry `transform: None` means "no transform", never "inherit the table's". §15 requires a test for this in both directions.
- **`tests/` is linted/formatted by nothing** — 118 test files repo-wide are unformatted. Do not "fix" them; formatting them breaks convention rather than restoring it.
- Merge with `--no-ff`; commit trailers name the actual authoring model.

## Known Issues, Not Yet Fixed
- **`ExporterDefinition.entries` is unbounded on a now viewer-callable path** (diagnosed in Phase 3's final review, not fixed). One `POST /exports/run` with a client-supplied `definition` can chain N whole-table exports (each O(model), ~80 MB model in play) in one synchronous request. No authorization boundary is crossed — a committed exporter has the identical property — but creating a committed one requires editor rights and a draft run does not. A `Field(max_length=…)` on `entries` would bound it. **Deliberately left for the owner: this is a spec-level decision, not a hygiene fix.**
- `AddTablePicker.svelte` — `aria-controls` points at a listbox only rendered while open, and there is no `aria-haspopup="listbox"`. Parked because `Sidebar/Search.svelte:187-189,209` and `Metamodel/MetamodelSearch.svelte:160-162` use exactly this shape; fixing it is a repo-wide a11y backlog item across all three, not a lone divergence.
- `tests/api/test_exports_route.py` — the ambiguity test's `fake_find` re-queries the DB twice inside the monkeypatch, and `monkeypatch.setattr(exports_routes.content, ...)` reads route-scoped but mutates the shared module attribute. Harmless, restored by monkeypatch; tidy only if you touch it.
- **`POST /tables/json-preview` still renders array shape only** (object-shape preview deferred in Phase 2). Only fix on user request.
- Phase 2 coverage nit: no test for `key_column` pointing into an honored group bucket. Traced safe, still open.
