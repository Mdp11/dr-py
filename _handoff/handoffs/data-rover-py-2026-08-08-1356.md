## Standing Constraints
- **Leases are the concurrency control, not OCC.** No `view_rev`/`artifact_rev` precondition is
  ever sent on an op. Do not add one — `UpdateArtifactOp.artifact_rev` being optional-and-omitted
  is what makes the lease load-bearing (CLAUDE.md "Lease rule").
- **The staged view buffer is an ORDERED JOURNAL, not a coalescing map** (unlike
  `artifact-edits.svelte.ts`). View ops are order-dependent (create → place-into → move), so
  there is deliberately NO per-entry revert; discard is all-or-nothing. Same reason the
  replay-conflict path drops the WHOLE journal rather than individual ops.
- **`applyViewOp` (`frontend/src/lib/state/view-ops.ts`) is a MIRROR of the backend applier**
  (`src/data_rover/api/view_ops.py::apply_view_ops`). Any change to one needs the same change in
  the other, or optimistic UI silently disagrees with the server. Two reviewers verified the
  mirror branch-by-branch; do not "simplify" either side independently.
- **The client throws on folder sibling-name clashes where the backend only warns.** Deliberate
  safe-direction strictness — a throwing op is never staged, so replay convergence holds.
- **Element placements never target the view root**; "move to root" is `remove_element`
  (`place_element` at root 422s). Artifact refs DO have a real root list.
- **Never send an empty commit** — the backend's empty-batch early return skips lock release and
  orphans leases until TTL.
- **Frontend commands must go through the pixi tasks** (they set `cwd=frontend`); a bare
  `pixi run -e frontend npm test` fails with "Missing script". Run `npm run lint` alongside
  `npm test`/`npm run check` — a mid-rewire task shipped a lint regression because it verified
  with only the first two.
- **Preserve the dense invariant comments** in the files you touch; they are load-bearing and
  were repeatedly cited by reviewers. Extend in the same voice.
- Process that worked and is worth repeating: plan → `superpowers:subagent-driven-development`
  (fresh implementer per task, task review after each, one fix round, scoped re-review) → final
  whole-branch review on the most capable model → one fix wave → merge locally.

## Known Issues, Not Yet Fixed
- **Excluded-pool gap (follow-up #1, DIAGNOSED).** `frontend/src/lib/components/Sidebar/view-tree.ts:263-269`:
  an element staged OUT of a folder leaves the in-view tree (correct — `_view` no longer places
  it) but never enters the "Not in view" pool, because the pool's id list comes from
  `GET /model/containment/roots/excluded`, which only reflects COMMITTED placements. The element is
  in neither region until commit or discard. Recoverable, but reads as data loss. Fix: mirror the
  existing hide-filter with an inject-filter over elements whose staged home went away.
- **The "staged view edits were discarded" notice is transient (follow-up #2, DIAGNOSED).**
  `frontend/src/lib/state/view.svelte.ts:161-180` routes it through `setLockNotice`, which
  `edit-gate.ts`'s `noticed()` clears on the very next successful lease acquisition of any kind.
  For a destructive event the user may never see it. Wants a banner.
- **`view → realtime → artifacts → view` import cycle persists**, worked around by a
  `setTimeout(…, 0)` deferral of the module-scope tap registration in `view.svelte.ts` (documented
  at length in-file). The reviewer's suggested real fix: extract the `getView` accessor into a
  cycle-free leaf module. Not urgent.
- **`routes/locks.py`'s `expand_targets` degrades against a cold `session.view`**
  (`src/data_rover/api/routes/locks.py:84`): a DELETE-intent folder lease does not expand over the
  subtree if `session.view` is `None` at `POST /locks` time, so the granted token is narrower than
  the holder believes. Two reviewers judged it safely deferrable — `create_commit` and `undo` both
  re-derive against the resolved view, so the failure mode is a false 409 for the holder, never a
  silent stomp.
- **`DELETE /view` clears `session.view` but leaves `ViewRow`**, so eviction resurrects the view
  (`src/data_rover/api/routes/view.py:115-118`). Follow-up #3 deletes the route, which moots this.
- **`create_commit` is ~300 lines with four near-identical unwind blocks**
  (`src/data_rover/api/routes/commits.py`). Called the most fragile function in the API package;
  worth refactoring before Phase 3 adds a fourth content family.
- **Pre-existing flake**: `tests/model/test_search_index.py::test_string_properties_indexed_non_strings_ignored`
  fails ~0.8% of runs (queries `"123"` while uuid7 ids are trigram-indexed). Re-run and move on.
- Minor, ledgered during the rewire and all judged safe to defer: `create_folder` omits the
  backend's `TEMP_ID_PREFIX` guard client-side; rename/move_folder clash-throws lack direct unit
