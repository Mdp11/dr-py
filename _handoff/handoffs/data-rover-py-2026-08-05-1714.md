- **Artifacts adopt the full lock→edit→commit flow** (user decision) — not instant-save-with-lock; history/diffs must fall out of the journal.
- **Elements keep BARE lock resource ids; only new types get prefixes (`art:`, `folder:`, `mm`)** — keeps the existing frontend lock badges and wire format working unchanged during the backend-only phase.
- **Model applier (`routes/ops.py::_apply_one`) must never receive artifact ops** — the `ModelOpIn`/`ArtifactOpIn` union split + pyright's `assert_never` is the enforcement; plan Task 3 explains it.
- **`/model/ops` rejects artifact ops permanently** (not a migration stub) — artifact edits go through `POST /commits` or legacy `PUT /artifacts` only.
- **Plans are written one phase at a time, after the previous phase lands** — later phases need real post-Phase-1 code to reference; writing them early bakes in stale line refs. This is why only the Phase 1 backend plan exists.
- Executor discipline: the plan has a Guardrail Protocol section (TDD, lint after every task, CHECKPOINT tasks run the full suite, one commit per task, STOP-and-report conditions). Follow it exactly; the one sanctioned existing-test change is called out in Task 7.
