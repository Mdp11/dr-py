**Rulings made this session (each with its reason — these are why the plan text and the code
now differ in places):**
- **A4 — `hoverLabel` returns `` `${relName}: ${src} → ${tgt}` `` for an ordinary two-box
  association, bare `relName` for a tether half.** Spec §4 mandates endpoint info in the LOD
  tooltip (box names are hidden at that zoom); the bare-name form the plan wrote dropped it.
  The tether-half carve-out exists because `buildDiagram` splits a boxed relationship into two
  halves, so the naive form renders nonsense like `Monitors: Building → Monitors`.
- **A5 — `TypeSearchHit` carries `matchStart`/`matchLength`.** Spec §6 requires the dropdown to
  highlight the matched substring; the plan's type had no way to express it. Values are free at
  match time. `matchLength` is the TRIMMED query's length (raw would over-highlight).
- **B1 — the plan's `'o'` search expectation was arithmetically WRONG.** It listed three hits;
  `Contains` also contains an `o`, so the real answer is four: `Observes` (prefix rank 0), then
  rank-1 alphabetically `Contains`, `Monitors`, `Zone`. Corrected in both Task 6 and Task 9.
  Independently re-verified twice. **If a future test disagrees, recompute from the fixture —
  do not weaken the matcher to fit an assertion.**
- **B2 — NOT NEEDED (recorded for completeness).** `buildDiagram` DOES emit `rel:Observes`
  (`needsAssocBox` at `frontend/src/lib/metamodel/diagram-build.ts:66-73` returns true on
  `abstract` OR `extends` OR "something extends it"; the fixture's `Observes` satisfies two).
- **B3 — NOT NEEDED.** `getMetamodelDiagramView()` reads only the editor buffer
  (`frontend/src/lib/state/metamodel-diagram.svelte.ts:304-313`), so component tests need only
  `initMetamodelEditor`, not `initMetamodelDiagram`.
- The handoff-era contingency about `parseDraft` not normalizing `source`/`target` shorthand is
  **resolved and moot**: it DOES normalize into `mappings`.

**Architecture (load-bearing — do not "simplify" these):**
- **Hover must NEVER rebuild `flowNodes`/`flowEdges`.** This is the premise of the whole feature
  set (fine at 20 nodes, wrong at 300). Verified true at Task 4: both array `$effect`s depend
  only on `built`/`specToNode`/`containmentRels`/`view.selection`, and the one bridge
  (`setDiagramAdjacency(buildAdjacency(built.edges))`) is keyed on the parsed metamodel alone.
- **LOD hides content with `visibility: hidden`, never `display: none` / DOM removal**, so box
  heights and therefore edge anchors are byte-identical in both modes. `nodeSize` and elk are untouched.
- **Each of the three node components has exactly ONE `.mm-node` CSS rule.** Tasks 3 and 4 both
  merged properties into it. Do not add a second block.
- `revealSelection` takes the flow helpers as a **parameter**; the caller owns `useSvelteFlow()`
  (hooks bind context at their call site). Confirmed working at Task 9's call site. Do not move
  the hook inside.
- Memo caches in `.svelte.ts` state modules are **plain `let`, never `$state`** — writing `$state`
  from a getter trips `state_unsafe_mutation` mid-render. See
  `frontend/src/lib/state/metamodel-diagram.svelte.ts:74-80`.
- All four features are **read affordances available to viewers** — nothing consults `readOnly`
  or `canDragLayout`.
- Colours are CSS tokens (`var(--…)`, `color-mix`) only, never hex literals.
- Dense docstrings explaining *why* are house style and are graded. A docstring that overstates
  what the code does is treated as a defect (this caused Task 1's only fix round).

**Known IDE noise, not a defect:** importing a `.svelte.ts` runes module as
`'../foo.svelte'` makes the TS server report "Module '*.svelte' has no exported member".
It is the repo's standing convention (see `frontend/src/lib/state/__tests__/metamodel-diagram.test.ts:24`)
and `svelte-check` passes. Tell reviewers so they don't burn a finding on it.
