## Standing Constraints
- **Phase ordering is the spec owner's (§16).** Phase 3 is the automation surface; do not pull Phase 4 (`transform` hook) or Phase 5 (bundle-draft export) forward. §16 says Phase 5 must be **re-confirmed before starting**.
- **Each phase lands green and is independently shippable** (`dr-tidy` + `core-test` + `frontend-test`) — spec §16.
- **Never block Save.** All strictness is a 422 at *export* time naming the offending entry, never at artifact save/commit time. This held through Phase 2 and must hold in Phase 3.
- **No-migration guarantee.** Every artifact payload that validates today must validate unchanged and export byte-identically until a user opts into a new option. New fields get defaults.
- **RENDER ONLY boundary.** Presentation settings never touch evaluation — cell values, row order and script cache keys stay computed off the original definition. `json_doc` is an engine parameter, never on `TableDefinition`.
- **Comments/docstrings are load-bearing** in this codebase and are treated as contract; `table_export_engine.py`'s header says its long comments moved there VERBATIM. Phase 2's final review made two comment-accuracy items merge-blocking. Budget for that.
- Everything runs through **pixi** — no global `python`/`pytest`/`ruff`/`node`; system node too old for eslint. Frontend tasks set `cwd=frontend`, so a bare `pixi run -e frontend npm test` fails.

## Known Issues, Not Yet Fixed
- **`BACKLOG.md:826` — K-11 · CSV export writes untrusted cell text through `csv.writer` unmitigated.** Diagnosed and verified: `api/table_export.py:117-132` hardens the xlsx writer with `strings_to_formulas: False` against untrusted model content becoming live formulas; `core/table/csv_export.py` has no equivalent, so an element named `=HYPERLINK(...)` becomes a live formula when the CSV is opened in a spreadsheet. **Deliberately kept** (sanitizing mutates data for the machine consumers CSV exists to serve; RFC-4180 has no formula concept) and documented in `csv_export.py`'s docstring. The user has NOT yet confirmed this posture — worth raising.
- **`BACKLOG.md:706` — F-16 · `EntryLayoutDialog`'s Save button is disabled while a split filename template is invalid** (`splitTemplateInvalid`), widened in Phase 2 from `json` to the whole json family. Pre-existing Phase 1 behavior, not new strictness, but in tension with never-block-Save. The standalone table dialog's equivalent gate is on **Export**, a different action.
