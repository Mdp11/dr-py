## Standing Constraints
- `lastInline` in `NavigationColumnEditor.svelte` and `RowSourceEditor.svelte` must stay `$state.raw` — deep `$state` returns a Proxy that leaks into the table definition and used to brick every edit with `DataCloneError` (regression test: `frontend/src/lib/components/Table/__tests__/ColumnManager.inlineToggle.test.ts`).
- `frontend/src/lib/table/columns.ts` mutators are copy-on-write at column granularity, NO deep clones — NavigationColumnEditor's mirror effect compares `columns[i].navigation.definition` by reference; deep cloning re-seeds every inline preview on unrelated edits (and was the structuredClone crash surface).
- `routes/tables.py` samples `rev = session.model_rev` exactly once per request — re-reading after the unlocked build/sort can poison the order cache under the new rev.
- Store's sparse-cache staleness protocol: `mergePage` splices only when `model_rev` AND `total` match; every reset path goes through `bumpGeneration` (which also clears `_inflightChunks`/`_chunkRetries`).
- `keep_empty` only affects expand-mode columns (see `build_rows`); the UI therefore only shows "Keep rows with no value" while "Split multiple values in multiple rows" is checked.
- The Scope (element) column: no "+ Element column" button; the last remaining element column's remove is disabled (UI-level only — `removeColumn` in columns.ts deliberately does NOT enforce it, since element-column-free tables are schema-legal).
- Rename input in ColumnManager is debounced 400ms with immediate commit on `change` — component tests must dispatch `change`, not `input`, for synchronous assertions.
- Backend concurrency stance for table reads: no write_mutex, benign races accepted; cache-miss request coalescing (single-flight) was considered and NOT implemented because the frontend always lands one full load (warming the cache) before fanning out chunk requests.
- Export uses `TableLimits(max_cell_elements=10**9, ignore_cell_caps=True)` — per-column `cell_cap` must never truncate exported cells.
