## Standing Constraints
- **Backend contract is frozen and reviewed** — build the UI to it; if you think a route
  is wrong, raise it rather than changing it, because each shape was argued through a
  final review.
- **Import never places artifacts in the view** — imported artifacts appear only in the
  flat artifacts list. The user explicitly reversed an initial place-at-root
  recommendation; the bundle format carries no placement data. Do not "helpfully" place them.
- **Import is stateless** — the client re-sends the whole bundle at confirm; there is no
  server-side staging. Bundles are KB-scale. Stateful/token staging was considered and rejected.
- **A 409 from `POST /artifacts/import` carries a fresh plan in `body.plan`** and now also
  the applier's real reason in `body.detail`. The client must re-render from `body.plan`
  rather than reusing the plan it submitted, or it loops forever.
- **`POST /artifacts/import` can also return a `create_commit`-shaped 409** (`{detail, model_rev}`,
  no `plan`) under genuine concurrency. A client keying blindly on `body.plan` breaks — handle
  both shapes.
- **Export and export/preview are viewer-allowed; `import/plan` and `import` are NOT**
  (planning is part of the write flow). A viewer must not see enabled import affordances.
- **`rev: null` in `ImportConfirmResponse` is a successful no-op**, not an error — it means
  everything was reused or skipped and no commit was minted.
- **The real frontend lint gate is `cd frontend && pixi run -e frontend npm run lint`** —
  `pixi run dr-tidy` does not catch everything the CI-equivalent lint does.
- Frontend tasks set `cwd = "frontend"`; a bare `pixi run -e frontend npm test` fails with
  "Missing script" because pixi runs it from the repo root. Use the `frontend-*` tasks.
- Process precedent (6 sessions running): plan → fresh implementer subagent per task →
  task review after each → final whole-branch review on the most capable model → ONE fix
  wave → merge `--no-ff` → delete branch. Push only on ask.

## Known Issues, Not Yet Fixed
All diagnosed and verified during the Phase 3 reviews; none block this slice.
- **The wizard route discards `import_project`'s returned skip list**
  (`src/data_rover/api/routes/projects.py` ~:119), so a wizard user gets no signal that
  artifacts were skipped. The CLI does print them. Surfacing it needs a `ProjectOut` field
  — this is the one backend gap worth folding into this slice (Plan step 4).
- The untrusted import path **skips unregistered kinds**, so an export → wizard/CLI import
  drops `diagram` rows; clone still carries them. Deliberate, documented in `CLAUDE.md`.
- `importer._landable_artifacts` checks kind before empty name while `derive_plan_ex` checks
  empty name first — an artifact that is both reports a different `reason` string per path.
  Cosmetic.
- `derive_plan_ex` issues one indexed `list_artifacts` per distinct kind even for create-only
  bundles, and `list_artifacts` loads full payloads for what is only a name pool.
- Ship-as-is minors recorded in the final review: the 422→409 remap's inert `ack_errors`;
  the unpluralized `"Imported 1 artifacts from Source"` default commit message (pinned by a
  test); `export_artifacts` re-fetching `Project` that `require_membership` already loaded;
  `assert project is not None` stripped under `python -O`; unbounded bundle/payload sizes
  with no body-size middleware.
- Carried from earlier phases: stale cross-ref comments in `routes/ops.py` ~:707/:714;
  `routes/locks.py::expand_targets` degrades vs a cold `session.view` (~:84, false-409 only);
  a `view → realtime → artifacts → view` frontend import cycle worked around by
  `setTimeout(…,0)` in `view.svelte.ts`; `_seed_view` conftest duplication ×4 files.
- Pre-existing flakes: the e2e auth/session family (`frontend/e2e/helpers/auth.ts:33`) and
  `tests/model/test_search_index.py::test_string_properties_indexed_non_strings_ignored`
