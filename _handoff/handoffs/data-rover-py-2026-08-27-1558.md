## Standing Constraints
- **Explicit `inputs` list, not whole-row visibility** — keeps the cache key small and recompute scoped to the column's own inputs (user chose this over (b) whole-row).
- **Named dict `value(elements, inputs)`, not positional list or kwargs** — survives input reordering; lint arity stays a simple count (user chose this).
- **Failures propagate** — pending input → pending cell, errored input → error cell `input '<name>': <msg>`; NEVER pass `[]` for a broken input, because the result would be cached under a key that cannot know the input was broken (user chose this).
- **Cache key stays byte-identical without inputs** — fourth `CellKey` component is `""` when no inputs, else a sha256 prefix of canonical JSON; canonical JSON already keeps `1`/`1.0`/`"1"`/`true` distinct, no type tags needed.
- **Invalidation needs nothing new** — the resolved input VALUE is in the key; element inputs are read through the guest facade so they land in the read-set.
- **Sweep resolves inputs live during serial enumeration**, following the existing script-as-source precedent (README "What counts as COVERED"); a pending/errored input counts the dependent cell as `dup_or_empty`/done.
- **Arity mismatch is symmetric**: 1-arg `value` with inputs AND 2-arg `value` without inputs are both rejected — 422 at save for inline code (schema validator, `entry_arity`), error cell at evaluation for a ref snippet (it is edited independently; `resolve_table_refs` uses `model_copy`, so no re-validation happens after inlining).
- **Duplicate refs allowed** — two inputs may name the same column under different names; no rule.
- **Import-cycle rule for the new module** — `core/table/script_inputs.py` imports `evaluate.py` at module level and nothing from `cells.py`; `cells.py` imports `script_inputs`; `evaluate.py` imports `evaluate_script_column` FUNCTION-LOCALLY (same pattern as `_expand_values`' `expand_property_values` import).
- Cycles are impossible by construction (backward-only `ColumnRef`s) — no runtime cycle check.
