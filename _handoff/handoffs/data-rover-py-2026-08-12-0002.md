## Standing Constraints
- **Scope is "lock mirroring only" — user's explicit choice.** Full HA (ownership
  leases + affinity routing + handoff, master spec `docs/superpowers/specs/2026-06-16-multi-user-collaborative-architecture-design.md` §12 Phase 7) is a FUTURE phase; this
  one must not obstruct it but must not attempt it.
- **Redis is an optional, degrade-graceful mirror — user's explicit choice.** Empty
  `DATA_ROVER_REDIS_URL` ⇒ NullLeaseMirror; a down Redis warns + cooldowns, never fails
  a lock route, commit, sweep, or hydration.
- **Approach A approved:** `LockTable` stays the only conflict authority; two-method
  `LeaseMirror` seam (`write`/`load`); whole-set JSON per project key
  (`dr:leases:{project_id}`, versioned envelope, key-TTL self-clean); write-through at
  five sites; restore-on-hydrate with ORIGINAL tokens (token continuity is the point).
  Per-lease Redis structures and Redis-authoritative locking were proposed and rejected.
- **Clock mapping happens only at the mirror boundary** — `Lease.expires_at` is
  monotonic; the mirror stores wall-clock epochs (`to_mirrored`/`to_leases`).
- **`mirror_session_leases` must take the write_mutex itself for the snapshot and do
  Redis I/O outside it** — the mutex is non-reentrant; call the helper only AFTER the
  route's own `with session.write_mutex:` block exits (deadlock otherwise).
- **The Phase 1–5 backend wire contract is frozen, ADD only** — this plan adds side
  effects, zero routes, zero response-shape changes. Adding `project_id: str` to lock
  route signatures is path-param binding, not a wire change.
