## Standing Constraints
- **Design decisions are locked** (see spec's Decisions table). Key ones and their
  reasons, so they don't get relitigated:
  - Row identity = tuple of **bindings** (row-source slots + one per expand column).
    Subsumes chains-mode; keeps RowKey hashable/cacheable.
  - Row-rooted navs use a `{kind:"row"}` **RowStart sentinel** (nav SCHEMA_VERSION
    2→3, additive) — NOT the Stage-1 id-equals-scope trick, because `_scope_ids`
    scans the whole model (O(rows×model)); RowStart is O(1) dict lookup and composes
    inside set expressions.
  - `present:false` (type lacks the property) is a **wire flag**, not client-derived —
    the client would otherwise resolve effective props per row for heterogeneous sources.
  - `columns.ts` is a **separate pure module** (mirrors `tree.ts`) — column reorder
    must remap every `ColumnRef.index`; that arithmetic belongs behind tested functions.
  - Sort: missing/empty **always last in both directions** (not nulls-first-on-desc);
    ties break on RowKey for total order. Property numeric only if EVERY scoped type
    declaring it gives integer/float datatype.
  - Row-order cache keyed on **resolved** definition fingerprint (refs inlined) so
    editing a referenced library nav invalidates without a model_rev bump.
  - Cell editing reuses the Inspector path exactly (`editLock`→`emit`→`DiffDrawer`→
    `POST /commits`) — never a new mutation surface.
  - Export is **server-side xlsx** (openpyxl, new dep in `[feature.api.dependencies]`),
    whole table, honouring sort; core stays xlsx-free (writer lives in `api/`).
- **CRITICAL implementation subtlety** (backend plan Task 4, fixed during self-review):
  `resolve_source_elements` must take an explicit `base_slots` param and read expand
  bindings from the row key via `_expand_slot_of`. A column sourced from an expand
  column must bind THAT row's single element, not the parent's whole reached set.
  Test `test_column_sourced_from_expand_column_binds_that_rows_element` guards it —
  do not delete/simplify it away.
- Frontend gotchas (from kickoff, still apply): `untrack()` idiom for register/
  unregister-in-$effect cards (see `PathCard.svelte`); `npm run lint` has TWO
  pre-existing prettier failures (`ProjectCard.test.ts`, `UsersTab.test.ts`) — don't
  fix, don't add new ones; frontend npm scripts MUST run via
  `pixi run -e frontend bash -c 'cd frontend && <cmd>'`.
- `ArtifactKind.table` already exists in the enum; `role` column CHECK already admits
  it — **no Alembic migration needed** for the table kind. `View.artifacts` root list
