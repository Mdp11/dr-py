## Standing Constraints
- **Execution method = full pipeline, subagent-driven.** User's explicit ask for this arc: `superpowers:brainstorming` → `superpowers:writing-plans` (a spec, then a task-level plan) → `superpowers:subagent-driven-development`. Same rhythm as M0 + M1-backend: fresh implementer per task + task review (spec+quality) per task + a final whole-branch review, TDD throughout, progress ledger. Cheap model for mechanical transcription tasks, standard for integration, capable for the final review; always name the model explicitly.
- **Ask before finalizing.** User: "If you have important points on which there are doubts, the agent doing the frontend part should ask first." Resolve Open Questions with the user during brainstorming, before the spec is locked.
- **Backend API is the contract — do not change it to suit the UI.** If the frontend genuinely needs a shape the backend doesn't provide, that's a scope decision for the user, not a silent backend edit. The response shapes in `schemas.py` are real and tested; write the plan against them.
- **`entry_points` is server-derived** — the client must never send/trust its own; read it back from the artifact after create/update. (Backend overwrites it from the code AST.)
- **Ops are dry-run** — a run returns proposed ops (`SnippetRunOut.ops`), never applied server-side. "Stage ops" pushes them into the **existing** staged-edits buffer (`ops.ts`/`apply.ts`); the commit path is the existing one. Do not build a parallel apply path.
- **`stale` flag** — `SnippetRunOut.stale=true` means a concurrent commit landed mid-run (model_rev moved); the UI must surface "results may be out of date, re-run" rather than silently staging possibly-wrong ops.
- **Cancel is a no-op in M1** — `POST /snippets/cancel` does real registry+ownership checks (so the button is wired and authorized) but the actual abort is deferred; a run only ends via `wall_timeout_s`. The Stop button should reflect this honestly (it deregisters/greys out, but the run finishes on timeout). Confirm the intended UX with the user (Open Q).
- **CodeMirror 6 is a new dependency** — added under `frontend/` (Node 22, `frontend/`-local npm; NEVER `pixi run -e frontend npm ...` from repo root). Python mode + a diagnostics gutter fed by debounced `/snippets/lint`. Confirm CM6 is the chosen editor with the user (Open Q) before adding the dep.
- **Read `frontend/README.md` before `frontend/src/lib/state/`** — CLAUDE.md mandates it; the reactive-state + optimistic-ops model is load-bearing and easy to break.
- **`docs/` is gitignored** — spec + plans stay uncommitted; do not try to commit them.
- **Do not push `main` / open a PR** — never requested.
