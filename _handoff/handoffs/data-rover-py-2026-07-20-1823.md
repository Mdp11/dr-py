- Root-cause facts (measured, real WASM runner): per-call 0.5 ms, instance boot ~200 ms, `open_session` ~5 ms; per-row `dr.elements()` scan snippet 16.3 ms/call → 49 s @ 3k rows. The freeze = whole-table serial passes × 30 s budget × errored→order-cache-skip loop (reproduced: two identical sorted requests each made 3,003 fresh guest calls). Don't re-investigate.
- Timeout/unavailable/memory/cancelled/pending results are NEVER cached (must stay retryable); runtime/syntax errors ARE cached (deterministic).
- A `failed` sweep is remembered per `(fingerprint, rev)` and never re-kicked at the same rev — without this the poll loop restarts the grind (spec self-review finding).
- A response whose cache-only pass saw pending NEVER reports `ready`, even if a sync sweep finished during the request (plan Task 7 `_status_from_job(pending_seen=True)` — its rows predate the sweep).
- Sweeps never block session eviction (`evict` cancels them; do NOT extend the evict guard clause).
- `TrustedRunner` must never move into `src/`; plan's API tests use purpose-built counting fakes instead (`tests/api/_script_fakes.py`, created in plan Task 6).
