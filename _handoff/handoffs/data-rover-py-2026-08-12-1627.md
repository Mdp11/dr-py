## Standing Constraints
- **Execute with `superpowers:subagent-driven-development`** — user's explicit choice
  over inline execution (2026-08-12).
- **Never wire `runValidation()`/`validateAll()` into open/commit paths** — the design's
  founding constraint: `POST /model/validate` with no ops runs the full pipeline over a
  possibly ~80 MB model (`routes/validation.py`, path 3).
- **The new GET must snapshot under `session.write_mutex`** — it is called during the
  background sweep by design; the sweep splices into `issues_by_owner` under that mutex
  (spec, "Backend" section).
- **`adoptIssues` drops only STRICTLY older revs** — equal-rev adoption must stay
  allowed because the sweep grows the server store without bumping `model_rev`.
- **`issue-source.ts` is a separate module on purpose** — it imports both stores;
  folding it into either creates the model↔validation import cycle (F-7 in BACKLOG is
  the cautionary tale).
- **`clearOverlay()` keeps `_lastError`** — a failed Validate's error strip must
  survive a peer commit (spec, overlay-store section).
- **StatusBar always shows committed counts** — approved behavior change: `validateAll`
  becomes a pure fetch; staged counts live only in the panel overlay. Existing tests
  asserting the old behavior (`validate-staged.test.ts`) are updated, not preserved.
- **The feed commit event stays delta-free for issues** — refetch (debounced 300 ms)
  was chosen over feed deltas because reconnect needs the refetch path anyway
  (spec, Decisions #3).
- Repo conventions that bit earlier sessions: everything through `pixi`; `dr-tidy`
  (ruff+mypy+pyright) is the authoritative typecheck — IDE import warnings for
  fastapi/redis are environment noise. Work in-place on the branch, NOT a worktree
  (pixi envs + ensure_guest.sh make worktrees expensive).
