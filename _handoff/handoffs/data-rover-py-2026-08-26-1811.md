## Standing Constraints
- **Bytes, never key.** `decode_snapshot` branches on the gzip magic; the `.json.gz` suffix
  is naming only. Reason: `tests/api/test_strict_mode.py:63` puts PLAIN JSON under
  `snapshot_key(...)`, and every pre-existing row has a `.json` key — one rule, no
  migration, no `encoding` column, no backfill, and both keep loading.
- **gzip level 3, module constant, not a setting.** Spike (scale 170): L1/3/6/9 =
  0.26/0.29/0.62/2.37 s for 6.7/5.8/4.9/4.5 MiB — 3 is the knee; nobody needs to tune it
  per deployment.
- **Batched encoder (`SNAPSHOT_BATCH` = 2000 per `json.dumps`), bracket-stripped.** Spike:
  1.58 s per-entity → 0.82 s batched, byte-identical to whole-document dumps (asserted by
  a test). Do not "simplify" back to per-entity dumps.
- **`iter_model_json` (indented) is untouched.** It is the `/model/save` + `/model/download`
  save-file contract with the frontend; the compact writer is a sibling.
- **Task 5 is gated by Task 4:** runs iff in-process `write_snapshot` at scale 320 is
  > 1.0 s. Prediction ~2 s, so expect it to run — but the number decides, and a skip is
  recorded in the BACKLOG, not silently dropped.
- **Background job takes `write_mutex` itself; snapshots the CURRENT rev; checks
  `get_registry().peek(pid) is session` under the mutex.** Reasons: a snapshot labelled rev N
  must be exactly the model at rev N (hydration replays N+1.. on top — a torn snapshot
  breaks restore-mode replay), so serialization cannot leave the mutex; any rev ≥ the
  trigger bounds the tail equally; and `discard` (delete-project) leaves the session
  unregistered with its rows gone — writing would violate the FK (`session.py:409-420`
  documents the same trap for the evict hook).
- **Rebind-forced, evict and baseline snapshots stay synchronous** — correctness, not
  bounding (`routes/commits.py:1426-1441`, `session.py:518-520`, `hydration.persist_baseline`).
- **Failure stance is log-and-drop** for the periodic snapshot on every writer, including
  `/model/ops` (which today would 500 after the commit landed) — matches `POST /commits`'
  existing "commit is durable, hydration will rebuild" warning.
- K-20: never build a search index on a transient model. K-6: `Commit.entity_states` NULL
  = reconstruct, never backfilled. Both untouched by K-21.
- `docs/` is gitignored — spec and plan never commit; everything else does. pixi for
  everything; `pixi run dr-tidy` must pass; `pixi run frontend-install` before `dr-tidy` in
  a fresh worktree. Integration = merge commit into `main` + push (`BACKLOG.md:1225`).
- Worktree harness guard: no compound Bash inside a worktree — plain commands or a
