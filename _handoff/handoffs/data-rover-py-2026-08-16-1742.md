## Standing Constraints
Decisions the user already made — do not relitigate:
- Positions are "commit required" (user's explicit choice over lock-only/auto-save):
  layout lands ONLY via journalled `metamodel.move_node` commits; but a layout-only
  commit must stay cheap (no metamodel swap, no full revalidation, no forced snapshot).
- Migration batches are the point: ONE mixed commit, at most one `metamodel.rebind`
  hoisted first, all other ops validated against the NEW schema — because "remove a
  property + fix all elements" must land in one rev.
- Rebind batches: owner-only (403), quiet-PEERS guard (caller's own leases fine),
  strict-mode EXEMPT (Phase 6B "engine stays inspectable"), forced snapshot, emit
  `rebind_event` not `commit_event`.
- `mm` lease flips honor-only → hard-verified at commit; this deliberately reverses a
  BACKLOG decision (contained: the honor-only contract dies with the retired route).
- `POST /metamodel/rebind` and `PUT /metamodel/layout` retire with NO legacy window
  (frontend is sole caller, migrates in the same change). `/metamodel/diff`, `/lint`,
  `GET /metamodel/layout`, `GET /metamodel/raw` stay.
- Amendment 1 (user accepted "it's fine"): undo across rebind-carrying commits 409s with
  push-back — restore-mode inverses are schema-checked at the core mutation boundary, so
  no replay order works both directions; layout-only undo IS supported. Do NOT try to
  make rebind undo work in this pass.
- Amendment 2: conflict backstop uses the single `mm` resource, NOT per-node `mmnode:`
  markers — the exclusive `mm` lease already serializes all metamodel writers.
- No Alembic migration anywhere in this feature (reuses existing tables/columns).
- Empty-ops journal rows stay reserved for `persist_baseline`'s marker; metamodel batches
  always have non-empty ops (keeps the staleness guard's overlap rule alive).
- `except MetamodelError, yaml.YAMLError:` in `commit_diff.py:291` is VALID Python 3.14
  (PEP 758) — a subagent flagged it as a syntax error; it is not. Don't "fix" it.
- Frontend module-cycle rule discovered during planning: `metamodel-stage.svelte.ts`
  imports ONLY `./ops` + svelte/reactivity; editor/diagram/checkout compose it via
  provider/listener registration (view-edits pattern) — a direct checkout→editor import
  would cycle through checkout→stage→editor→checkout.
