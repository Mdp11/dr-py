## Standing Constraints
- **Hard break, no aliases** — user explicitly chose no backward compat for saved snippets; old names must NOT survive as deprecated aliases.
- **`incoming()`/`outgoing()`, not `in()`** — `in` is a Python reserved keyword; `el.in()` is a SyntaxError. User approved the rename.
- **Facade-surface-only rename** — wire protocol keys (`"type"`, `"type_name"`), core `type_name`, read-set tag names (`"scan"`/`"el"`/`"out"`/`"in"`/`"children"`/`"parent"`), and memo-key shapes are unchanged; `api/invalidation.py` untouched. This protects cache-invalidation soundness.
- **Guest-side hop filtering** over the memoized unfiltered hop response + internal bridge `descendants` op (`kind: "element"|"relationship"`) — bridge-side filtered ops were rejected (memo-key explosion, invalidation risk). `descendants` records NO read-set tag (metamodel immutable per session).
- **`Element.name` = `name_of` semantics** — `None` when unnamed (user revised away from id-fallback); resolution via `core/model/naming.py` (exact-lowercase `name` first, then `Name`/`NAME`, list-valued names).
- **`expected=` must be int ≥ 1, bools rejected** (`True` is an int subclass); check runs on the *filtered* count; mismatch raises new `CardinalityError(BridgeError)` exposed as `dr.CardinalityError`; `expected=1` returns a bare `Relationship`.
- **`dr.elements` kwarg is `stereotypes=`** (not `types=`) — rule-1 consistency; user saw and approved this in the design.
- **YAGNI, user-approved**: no `Relationship.name`/`.set()`/`.delete()`; `value()`/`step()` keep rejecting Relationship returns.
- FACADE_SOURCE must stay stdlib-only, import-free, Py3.10-compatible guest source; every projection handed to snippet code goes through `_copy_projection` (memo aliasing invariant, load-bearing).
- Docs tripwire (`core/script/docs.py`) hard-fails undocumented public facade members — every new method needs a docstring with `Example:`.
- Commit style: `feat(script):` / `fix(script):` etc., matching repo history.
