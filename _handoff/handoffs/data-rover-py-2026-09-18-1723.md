- **Sub-project A is four plans**, written one at a time so each learns from the last: (1) package + value layer + golden pipeline [this], (2) Python snapshot v2 + state digest, metamodel, store, indexes, mutation boundary, (3) op applier + working copy, (4) snapshot reader, engine digest, benchmarks.
- **Value model (AD-21):** JS `number` ⇔ Python `int`, `bigint` beyond ±(2^53−1), EVERY float is a `PyFloat`, the strings `"Infinity"`/`"-Infinity"`/`"NaN"` stay strings. Lines are routed by a regex pre-scan: exact hand-written parser only for lines holding a float / ≥16-digit int / bare non-finite / `-0`; native `JSON.parse` otherwise.
- **The Python core is the oracle.** A failing golden test means the engine is wrong. Never hand-edit a fixture, never loosen a scenario.
- **`-0` must take the exact path:** native `JSON.parse("-0")` is `-0`, Python gives `int 0`. Found by the oracle check; already in the plan's regex (`-0(?!\d)`).
- **Unicode-escape trap (tooling):** the Write/Bash tool layer decodes `\uXXXX` in tool-call text into literal characters (`\\uXXXX` and `\U…`/`\u{…}` survive). Strings stay equal but U+E000/U+FFFF become invisible and `é` looks like `é`. When writing the plan's files, produce escapes via a script (`chr(92) + "u00e9"`) or post-process: non-ASCII char → escape, then verify with `LC_ALL=C grep -rnP '[^[:ascii:]]' tests/golden engine/test` — only `café` in `engine/test/value/serialize.test.ts` may show. Never put a NUL byte in a markdown file (it made `grep` go silent on the plan once).
- **Use pixi's Node, never system `node`** (system is v18; eslint 10 crashes with `util.styleText is not a function`). `pixi run -e frontend …` / the `engine-*` tasks give Node 22.22.
- **TypeScript in `engine/src`: erasable syntax only** (`erasableSyntaxOnly`), `.ts` import specifiers (`allowImportingTsExtensions`), `lib: ["ES2023"]`, `types: []` — so Node can run sources by type stripping with no build, and the compiler enforces "no DOM, no Node built-ins". No parameter properties, no enums.
- **Fixture files are parser-independent:** floats as IEEE-754 hex, ints as decimal strings, dicts as ordered pairs (`tests/golden/tagged.py` ↔ `engine/test/golden/load.ts`), so TS tests read them with plain `JSON.parse` and never depend on the parser under test.
- **`pyKey` mirrors `_frozen`, not general Python equality:** `{}` and `[]` share a key, `{"a":1}` equals `[["a",1]]`, `True == 1 == 1.0`, `-0.0 == 0`. `pyEquals` was dropped from A (YAGNI) — it is sub-project C's need.
- **Scope cuts for A:** `core/view` is not ported (UI-only; `validate_view` moves to C); engine takes a validated metamodel as JSON (`GET /metamodel` shape), no YAML/`check_metamodel` (AD-22); no trigram index (AD-13); engine never mints real ids (staged creates keyed by `tmp_` id; a test-only `idFor` hook mimics `SequentialIdGenerator`).
- **Digest hash (CT-3):** first 8 bytes of SHA-256 over `utf8(id) ‖ 0x00 ‖ ascii(rev)`, XOR-folded. CRC32 rejected: linear, an XOR fold cannot see two same-length ids swapping `rev`s.
- **`set_property` always bumps `rev`, same value included** (verified at `src/data_rover/core/model/model.py:89-92`; one survey agent claimed otherwise — it was wrong). `delete_property` of an absent key is a no-op.
