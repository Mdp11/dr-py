## Standing Constraints
- **The design is decided by measurement — do not reopen it.** The spike (spec table) says
  trigram re-derivation is ~85 % of a warm write (75.8 → 11.6 µs with it stubbed) and ~95 %
  of a cold first touch (129.8 µs), the property-list copy is 2.5 µs per check, rekey/roots/refs
  ≤ 9 µs each. Hence three legs (spec § "K-23 design" / Design): (1) cached frozenset names on
  `_Caches`, (2) `on_property_changed(entity, prop, old_value)` diffing from the changed value,
  (3) `_trigrams_of` entry ⇔ indexed (`()` included), cold elements left to the chunked build.
- **Leg 3 narrows a K-20 sentence, deliberately**: "hooks maintain postings regardless of
  readiness" becomes "for every element that has a `_trigrams_of` entry". Every existing
  search test was checked against it (`tests/model/test_search_index.py`,
  `tests/api/test_search_index_build.py::test_multi_chunk_build_skips_edited_and_deleted`) —
  final-state assertions all hold; one docstring goes stale and Task 3 rewrites it. The entry
  must exist even when empty, or a text-less element looks builder-owned forever — Task 3 (g)
  fixes `_update_trigrams`'s early return for exactly this (a plan self-review catch).
- **The diff is exact only for plain-string (or absent) old/new values with no list-valued
  `name`-keyed property** — `name_of` reads inside such a list. Every other case MUST fall back
  to `_update_trigrams(eid, _element_trigrams(el))`. Removal candidates are verified by
  substring against the other fields (id, type, other str props) — that is what makes it exact
  without per-field storage. `verify_consistent` compares the search structures with a fresh
  build, so every test ending in it checks the diff.
- Prototype correctness was verified at 320k: 0 of 3000 mixed-edited elements differ from a
  full derivation; `verify_consistent` passes afterwards (57 s). Task 4 repeats this.

## Deferred — Do Not Do
- **A bulk `restore_element(..., properties=...)`** for the replay tail — per-property hooks
  are the contract; leg 3 removes the cost instead (spec K-23 non-goals).
- **Diffing refs / rekey / roots per property** — ≤ 9 µs each; declined.
- **The `zip` trigram idiom / touching `_element_trigrams` or the chunked build's cost** —
  measured no faster; declined.
- **Per-field trigram storage** — multiplies the index's dominant memory; the substring
  check buys the same exactness. Declined.
- **Bypassing the hooks globally under `search_ready=False`** — hook-created elements must be
  indexed by the hooks (the build's id snapshot predates them); ownership is per element.
- Everything K-22/K-21/K-20/K-6 already deferred: folding the sequence number into
  `uniq_groups`, a sequence field on `Element`, the per-sweep position-map hoist, comparing
  `element_order` numbers to a rebuild's, zstd, an `encoding` column, serialize-outside-the-
  mutex, posting-set shrinking, `entity_states` backfill, journal-based `GET /commits/{rev}/model`.
