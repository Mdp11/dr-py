## Standing Constraints
- **Preserve file ids on staged creates** — user chose it over server-minted ids: CR chains applied across separate commits and a re-compare after Replace must not churn. Mechanism: optional `id` hint on `create_element`/`create_relationship`, applier uses `Model.restore_*`, journal keeps only canonical `temp_id` (Task 1).
- **Both flows are dialogs** (user choice): one `ModelChangeDialog.svelte` with `mode: 'compare' | 'apply-cr'`; the `/p/[projectId]/compare` page and `ApplyCrDialog.svelte` are deleted; both entries live in the Model dropdown, the flat Apply CR button goes.
- **No automatic preview** (user requirement): explicit **Preview diff** / **Create CR** / **Replace** (compare) and **Preview diff** / **Stage edits** (apply-cr) buttons; nothing fires on file selection.
- **Server proposes, client stages** (approach A, approved): `POST /model/compare` and reworked `POST /model/apply-cr` are dry runs that never mutate/journal/validate; the client stages via `stageProposedOps` and `POST /commits/preview` validates. Approach B (client-side diff over a full `GET /model` pull) rejected — ships 80 MB and duplicates the server gate; approach C (session-replace apply) rejected — bypasses locks/journal.
- **Multiple CRs apply sequentially** (user: "order is important"): CR2 sees CR1's result; the first conflicting CR 409s with `cr_index`.
- **Replace / Stage edits require an empty model staged buffer** — the proposal is computed against the committed model; pre-existing staged edits would surface as conflicts or double edits. Snippet staging keeps its looser rule.
- **Replace is disabled while swapped** — it is session → file by definition; Swap only affects Preview and Create CR.
- **Element retype is a 422**, not delete+create — no retype op exists and delete+create would cascade through containment children.
- **Relationship endpoints on same-CR additions use the element's temp id** in the proposed batch — so the client stages them lock-free and `id_map` resolves them; property refs keep real ids.
- **`ops_for_change(cr)` takes only the CR** (spec wrote `(base, final, cr)`; the CR carries every before/after needed).
- `/model/compare` is in `authz._READ_ONLY_POST_SUFFIXES` (viewer may compare + Create CR); `/model/apply-cr` stays a write (its only consumer is staging).
- Post-stage feedback uses `setLockNotice(...)` — it is the status bar's only transient notice channel; the dialog closes on success.
- BACKLOG **P-23** is this work; **F-9/K-6** (history diff) are adjacent and deliberately untouched.
