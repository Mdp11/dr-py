## Standing Constraints

- **Execution mode: subagent-driven** (`superpowers:subagent-driven-development`),
  chosen by the user over inline execution — fresh subagent per task, review
  between tasks.
- **JSON config lives on each column**, not on `TableDefinition` as an
  index-keyed map. Column indices move under reorder/insert/remove — the repo
  already carries `remapTableSortForRemove/Move/Insert` to keep a *single* index
  valid — so settings attached to the column travel with it for free.
- **Field name is `json_export`, never `json`.** Pydantic v2 still carries a
  deprecated `.json()` method that a field named `json` would collide with.
- **`format` field on the existing `/tables/export`, not a second route.** The
  202/completeness-probe preamble is the subtlest logic in `routes/tables.py`
  and both formats need it identically; a second route would duplicate it.
  `/tables/export` is also already in `authz._READ_ONLY_POST_SUFFIXES`.
- **Grouping is slot arithmetic, never value comparison.** Two rows share a group
  exactly when every non-grouped row-key slot matches. If you find yourself
  comparing cell *values*, you have taken a wrong turn.
- **Grouped output nests, and unwraps singletons.** Columns transitively sourcing
  the grouped column nest with it as an array of objects; a group holding only
  the grouped column flattens to an array of scalars.
- **Failed/uncomputed cells render `{"$error": ...}`, not `null`.** A consumer
  must be able to tell failure from emptiness.
- **`group: true` is tolerantly IGNORED** on a collapse, hidden, or deleted
  column rather than 422'd — the column editor can flip expand->collapse at any
  moment and rejecting would block exporting the whole table.
- **`render_json` receives UNFILTERED rows** (unlike the xlsx path, which
  pre-slices). It indexes cells by definition column index and skips hidden
  columns via their `None` key.
- **Core must not import from `api/`.** This is why `NOT_COMPUTED_MESSAGE` moves
  from `api/routes/tables.py` to `core/table/cells.py` in Task 3.
- **`SCHEMA_VERSION` stays 1.** Every added field is optional and nothing
  enforces equality on it.
- Everything runs through **pixi**; there is no global `python` or `node`. The
  frontend npm scripts MUST run from inside `frontend/` (`pixi run -e frontend
  bash -c 'cd frontend && npm test'`) — a bare `pixi run -e frontend npm test`
  fails with "Missing script".

## Deferred — Do Not Do

All deferred by the user during brainstorming, in favour of YAGNI. Do not
"helpfully" add these back:

- **Envelope and NDJSON document shapes.** The user chose bare-array-only; the
  renames, grouping, and element-format settings *are* the customization.
- **An "omit empty keys" toggle.** Keys are always present, empty is `null`.
- **Dotted key paths for arbitrary nesting.**
- **JSON import.**
- **`show_row_numbers` in the JSON output.** Ignored on purpose — an array index
  already numbers the rows.
- **A TypeScript reimplementation of the grouping algorithm** for the settings
  preview. That is exactly why `POST /tables/json-preview` exists.
  `defaultJsonKeys` in TS is display-only (input placeholders) and is the single
  deliberate exception.
