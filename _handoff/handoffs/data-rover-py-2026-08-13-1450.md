## Standing Constraints
- **RENDER ONLY**: evaluation (`build_rows_ex`/`order_rows`/`iter_export_rows`/script context) always gets the ORIGINAL `TableDefinition`; override/presentation copies feed only layout/render. Reason: cell values, row order, and script cache keys must be independent of export presentation (existing invariant, spec §3.4).
- **Strict template**: a `${name}`-less filename template is 422 at export and blocked in the dialog — user explicitly chose reject over normalize (the ONE strict export setting; everything else drift-normalizes).
- **Split files are always arrays**, concatenation reproduces the unsplit export — user choice (type-stability for consumers).
- **Full override set per entry**, initialized by copying the table's settings at add time; unmentioned columns get DEFAULTS, never the table's own current settings. Reason: the two config sets must not bleed either direction.
- **Tables only; one zip; per-entry format** — user choice (navigations have no export pipeline).
- **`POST /exports/run` with id in the body**, not the path: `authz._READ_ONLY_POST_SUFFIXES` matches fixed suffixes only.
- **Migration 0010 widens `project_artifacts.kind` VARCHAR(12)→VARCHAR(32)**; there is NO CHECK constraint to rebuild (`SAEnum(native_enum=False)` without `create_constraint`). "custom_export" is 13 chars — without the widen Postgres rejects writes.
- **Deterministic zips**: fixed `ZIP_DATE_TIME=(1980,1,1,0,0,0)` so identical content zips byte-identically (mirrors the WASM runner's determinism stance; makes tests exact).
- **Never commit `docs/superpowers/`** — gitignored by explicit repo convention (BACKLOG §10), overriding the brainstorming skill's commit step.
- Never `git -C` to the main checkout from the worktree session — the harness refuses redirected git; also avoid the word "source" inside compound Bash strings (sandbox false-positive observed).
