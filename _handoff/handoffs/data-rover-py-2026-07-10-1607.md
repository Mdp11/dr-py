## Standing Constraints
- Fix strategy chosen by user: targeted in-memory hardening (Approach C) now; Postgres-resident model (A) is the endgame at ~1M+ entities; embedded-store (B) rejected (SQLite single-writer ceiling). The search index must follow C: in-process, maintained at the Model mutation boundary.
- New secondary indexes go in `IndexSet` (indexes.py docstring calls it the single choke-point) and must be: incrementally maintained by the existing mutation hooks, recomputed in `rebuild()`, and asserted in `verify_consistent()` — exactly like `roots_order`.
- `/model/elements` keeps its **insertion-order contract** for non-search listing (docstring + tests assert it); a search index must not disturb the unsearched paging path.
- sortedcontainers type-ignore is quarantined in `_sorted.py` — no new type-ignores elsewhere.
- Validators/pipeline hooks must stay O(entity); whole-model work goes in `validate_global` or background sweeps. Same discipline applies to any per-mutation index maintenance (keep it O(1)-ish per op — display-name calls were the hidden cost that made roots pages slow).
- `GET /model/status` must never hydrate (`SessionRegistry.peek` only); frontend Zod schema depends on exact field names.
- Warm-open skeleton design (this session): the handoff-suggested gate `hasModel && !viewResolved` NEVER opens because boot() resolves the view BEFORE the summary — the shipped design is a `project-open.svelte.ts` flag set around boot()/onReloadModel() + `rootsLoaded` + pure `treeBodyState()` resolver (frontend/src/lib/components/Sidebar/tree-empty-state.ts). Don't "simplify" it back to the viewResolved gate.
- `treeBodyState` parity choices (deliberate): known-empty model says "Model is empty." even mid-open; rootCount>0 (incl. view folders) always paints rows; idle metamodel-only project (summary never loads) shows "Model is empty.", not an endless skeleton; roots-loaded-but-filter-hides-all renders the blank rows area (old behavior).

- Keyless element types produce n-1 uniqueness-duplicate issues for identical-props elements — accounted for in sweep tests (`_expected_issue_count`).
- UUIDv7 ids sort before uppercase display names — don't write ordering tests with absolute positions for unnamed elements.
- Tests/api/conftest.py pins `DATA_ROVER_VALIDATION_SWEEP_SYNC=true` and `DATA_ROVER_IDENTITY_PROVIDER=header`.
