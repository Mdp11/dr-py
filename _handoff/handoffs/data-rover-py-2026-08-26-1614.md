## Standing Constraints
- **Design (settled in the plan, argued from the spec):** every journal writer stores the
  touched entities' FULL before/after state in a nullable `Commit.entity_states` JSON column
  (shape in `api/commit_states.py`'s docstring, Task 2); `NULL` = "not captured → reconstruct"
  (old rows, batches over `ENTITY_STATES_MAX = 5000`, baseline rows). Never backfill. Reason:
  the inverse `properties_patch` carries only touched keys, so a "reference list" (the owner's
  BACKLOG proposal) cannot render `modified`.
- **Scope addition discovered while planning:** the frontend's per-commit Diff never called
  `GET /commits/{rev}/diff` — it reconstructs twice via `GET /commits/{rev}/model` client-side
  (`HistoryDrawer.svelte:45`). Task 5 switches it; the backend route alone would not have fixed
  the owner's complaint. The two-revision **Compare** stays reconstruction-based (O(model) by
  design — see Deferred).
- Both diff paths feed ONE renderer (`_element_diffs(states)` over `(before, after)` pairs) so
  output is byte-identical; Task 4's `test_null_states_fall_back_to_reconstruction_byte_identically`
  pins it (snapshots carry entity `rev`, so `rev` matches across paths too).
- First-touch snapshot primitive is `ElementOut.from_core(element)` (`dataclasses.asdict`
  deep-copies nested containers) — do not hand-roll a shallow copy.
- No opt-out flag for the snapshots on replay/rollback paths (cost is the same order as the
  inverse-unit construction already there) — decided in the plan; revisit only if K-23's replay
  measurements show it.
- SDD process rulings (all in the ledger): T3's mid-file test imports may be hoisted to module
  top; baseline ran concurrently with Task 1 (informational only); branch rename noted.
- K-20 constraints still bind: never build a search index on a transient/reconstructed model;
