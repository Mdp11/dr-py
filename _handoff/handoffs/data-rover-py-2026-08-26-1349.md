## Standing Constraints
- The search index is built OUTSIDE `IndexSet.rebuild()` — measured 22.5 s of the 30 s bulk build and ~1.5 GB of the 1.78 GB index RSS at 320k, and most `rebuild()` callers (rebind view/preview/commit, apply-cr copies, history reconstruction, migration CLI) never search.
- `search_candidates` returns `None` while `search_ready` is False — `routes/read.py::list_elements` already scans on `None` with byte-identical results, so no route changes; never change `_search_score`.
- Mutation hooks maintain postings regardless of `search_ready` — the chunked background build depends on it (an element edited before its chunk lands is already indexed and skipped; deleted ones are absent and skipped).
- Rebind sites (`api/metamodel_ops.py:186`, `routes/commits.py:460/595/644`) use `rebuild(keep_search=True)` — the indexed text (id, type name, string props, `name_of`) is metamodel-independent, and without it every rebind preview would drop and rebuild the index.
- `rebuild()` must clear `_element_ref_props`, `_relationship_ref_props`, `_key_specs`, `_is_containment`, `_out/_in_key_rel_types` — verified stale bug (see Known Issues); Task 1 includes it, Task 2 tests it.
- `search_ready` is True on a fresh `IndexSet` — an empty model's empty index is complete, and it keeps every hook-built unit test (`tests/model/test_indexes.py` etc.) unchanged.
- `DATA_ROVER_SEARCH_INDEX_SYNC=true` pinned in `tests/api/conftest.py`, mirroring `VALIDATION_SWEEP_SYNC` — the API suite must keep seeing a complete index after load.
- The build is kicked from hydration, `_install_model`, AND the deprecated `POST /model` / `PUT /model/snapshot` — `tests/api/test_search_parity.py` loads through `POST /model` and would become scan-vs-scan (vacuous) otherwise.
- Eviction cancels a running build rather than waiting for it — the snapshot does not depend on the search index (unlike the validation sweep, which blocks eviction).
- `GET /model/status` is unchanged — nothing waits on the search index.
- `docs/` is gitignored: plan and spec are never committed. Integration is a merge commit into `main` (repo convention, see `git log`), then push (BACKLOG: pushing is no longer deferred).
- Every command through pixi; `pixi run dr-tidy` must pass (ruff + mypy + pyright; pyright includes `tests/`, so no `# type: ignore` shortcuts in tests).
- Dead end, do not retry: dropping the element id from the indexed text buys nothing (30.0 s → 28.3 s measured); the cost is the property text.
