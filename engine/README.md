# Engine (`engine/`)

Commands: `pixi run engine-install | engine-test | engine-check | golden-fixtures | engine-bench-data | engine-bench | engine-bench-browser` (tasks set cwd = `engine`).

The TypeScript engine of the target architecture (`architecture/`), built bottom-up. It holds the **value layer, the metamodel, the record-graph store, the op applier, the working copy, the snapshot reader and the state digest** — all of sub-project A — and, from sub-project B, the **steps layer, the read surfaces and the service** (the CT-4 dispatcher and its scheduler), and, from sub-project C, the **artifact set and the first evaluations** (criteria search and navigation, which the app's `criteria` and `navigation` surfaces take from the engine by default) and the **built-in validators**; the server never imports it, and the frontend imports its TYPES only — the sandbox's worker (`sandbox/README.md`) is its one host, and the frontend's shell (`frontend/src/lib/engine/README.md`) talks to it over a `MessagePort`.

- **`src/` has no DOM and no Node dependency** (`lib: ["ES2023"]`, `types: []`), is erasable-syntax-only, and imports with `.ts` specifiers, so a worker, Node and vitest all run the sources unbuilt.
- **`src/value/`** reproduces the Python core's view of JSON values. A `number` is always a Python `int`; every `float` is a `PyFloat`; integers past 2^53 are `bigint`. `parseJson`/`parseLines` route each line: a regex pre-scan sends lines holding a float, a 16-digit integer, a bare `Infinity`/`NaN` or `-0` to the exact parser and everything else to native `JSON.parse`, many lines to a call — which is why `parseLines` refuses a line holding more than one document instead of shifting every document after it. `pyDumps` is `json.dumps(ensure_ascii=False, allow_nan=False)` byte for byte; `pyFloatRepr`, `pyRepr`, `cmpCodePoint` and `pyKey` mirror `repr(float)`, `repr(str)`, `str` ordering and the uniqueness signature (`_frozen`). `pyLower` / `pyStrip` are `str.lower()` / `str.strip()` of Python 3.14 whatever Unicode version the host carries (Node's `toLowerCase()` differs at 28 code points, `trim()` from `strip()` at 6): generated tables — `lower-tables.ts`, written by `pixi run golden-fixtures`, never by hand — plus Python's final-sigma rule, held to `py_lower.json` over every code point. The search criteria's "JavaScript" coercion is Python's `str()` and `float()` in fact (`core/search/criteria.py`'s `_js_str` / `_to_number`): `jsStr` mirrors `_js_str`, `pyReprValue` the `repr` it and `_to_number` fall back to for a container, and `toNumber` `_to_number` itself, throwing `PyOverflowError` where `float(int)` raises `OverflowError`. `pyFloatOf` is `float(str)`: every Unicode decimal digit and `str.isspace()` code point past ASCII becomes its ASCII digit or a space — an ASCII code point, control characters included, is untouched, so `float()`'s own leading/trailing strip (the six classic whitespace characters, narrower than `str.isspace()`) still governs what parses — before the grammar runs and underscores are dropped for `Number()`. Its digits and whitespace come from `digit-tables.ts` (generated, `tests/golden/coerce_tables.py`), held to `py_coerce.json`. `translatePyRegex(pattern, mode)` is `re.search` / `re.fullmatch` (a criterion's `matches`, a pattern facet) in JavaScript. It answers `ok` with a `test(subject)`, `invalid` where `re.compile` certainly refuses the pattern (which then never matches), or `unsupported` with a one-line reason: anything outside its subset is `unsupported`, never guessed, and its caller sends the call to the server. A recursive-descent parser that follows `re`'s own over code points emits a `u`-flag `RegExp` source (never a string replacement over the pattern) and leaves nothing to JavaScript's semantics: the dot is `[^\n]`, `^` / `$` / `\A` / `\Z` / `\z` are look-arounds (`$` also before a final newline), `\w \d \s` and their negations are explicit classes, `\b` / `\B` look-arounds over the `\w` class, named groups become numbered ones, the whole is anchored natively (`^[\s\S]*?(?:…)` for a search, `^(?:…)$` for a full match) because V8 also tries a `u` search between the halves of a surrogate pair, where every look-around sees no neighbour, and IGNORECASE is not JavaScript's `i` (its folding differs at `İ` and `ı`, and with the host's Unicode) but `re`'s: a cased literal, or a class holding a cased member, becomes the class of every code point whose `re` lowercase is a member's lowercase or one of `re`'s extra equivalents. Outside the subset: flags other than leading `(?i)` / `(?m)` / `(?s)`, possessive quantifiers, atomic, conditional and comment groups, `\N{…}`, a class Python reads as a future set operation or a nested set, a look-behind of varying width, a repeated look-around, a back-reference under `(?i)`, in a look-behind or to a group that may not have matched (JavaScript matches an unset group as empty, `re` fails it), a class past U+FFFF under `(?i)`, a count past 65535 and a translation past 4 MiB. The classes and the case data come from `regex-tables.ts` (generated, `tests/golden/regex_tables.py`, which also asserts the two properties of `re`'s case data the translation leans on); the answers are held to `py_regex.json`, patterns × subjects in both modes plus a few patterns against every code point. Translations are memoized per pattern and mode, the 256 used last.
- **`src/metamodel/`** — `Metamodel.fromJSON(doc)` takes the `GET /metamodel` document (validated by the server; the engine parses no YAML and runs no `check_metamodel`) and builds every lookup of the Python `Metamodel` up front, under the same names in camelCase. `Multiplicity.parse` mirrors the Python parser, error text included.
- **`src/model/`** is the store: one fixed-shape record per entity (`ElementRec`, `RelRec`), adjacency and containment parents as arrays of record references ON the records, and `Model` as the single mutation boundary, with the Python method set and error texts (`ModelError.kind` is `key` / `value` for `KeyError` / `ValueError`). The engine never mints ids: `createElement(typeName, id)` and `connect(…, id)` take them. Entity order is state: each record has an `ord`, `elements()` / `relationships()` iterate in it, and a record restored WITH its old `ord` goes back to its old place (the Python core always appends). `IndexSet` keeps by-type, uniqueness, references and root order; adjacency order is unspecified, so anything observable sorts by code point. Uniqueness buckets are keyed by a 53-bit hash of the `pyKey` text and confirmed by the exact text at query time. `loadElement` / `loadRelationship` + `rebuildIndexes()` are the bulk path — non-strict like `build_model_from_dicts(strict=False)`, the same refusal texts as `SnapshotError` — and stricter than Python in two places: an id shared by an element and a relationship, and an array-index property key (`"0"`) at any depth, which a JavaScript object cannot keep in insertion order. Committed state enters through `insertElement` / `insertRelationship` / `overwrite`, which check no type (a model may hold one its metamodel no longer has) and take `rev` as given instead of counting it.
- **`src/ops/`** — `applyBatch(model, ops, {restore, idFor})` is the port of `routes/ops.py::_apply_batch` for the six model ops, in the wire's shapes: temp ids resolved through `idMap` in ids, ends and property values (strings and lists, never inside a dict), `id` hints, restore mode, merge patches, the cascade read before it happens, first-touch changed/deleted sets kept disjoint, the `recreated` sets (the changed ids the batch deleted and created again), inverse units and `inverseOps()`. `idFor` decides a created entity's id and is the identity by default — a staged entity lives under its temp id. A refusal is an `OpError {status: 422, detail}` with the server's text, the quote-stripping of `_error_detail` included (`No element with id 'ghost`). One deliberate difference from the server: an op carrying an array-index property key at any depth is refused. A refused batch leaves NO trace on either side — `rewind(model, result)` puts every touched entity back from its first-touch before-image (properties, `rev`, `ord`), and the server's `_rollback` is its port. A record that outlived the batch still has the `ord` of its image and is rewritten in place; anything else under a touched id is removed and the image inserted at its old `ord`.
- **`src/working/`** — `WorkingCopy` owns a `Model`, the committed `rev` and state digest, the staged batches and the committed image of every entity they touched (`committedElement` / `committedRelationship`, `isStaged`). `stage(ops)` applies a batch in place; `unstage('all' | {batch} | {entity, incident?})` and `applyDelta(delta, own?)` are both a rebase — rewind every staged batch newest first, change committed state, replay in order — and a batch that no longer applies is parked in `conflicts()`, never dropped. `applyDelta` follows CT-2 (`applied` / `duplicate` / `gap`), reads the delta's entities with the bulk loader's checks before anything moves, writes them through the committed-state methods (the ids the delta names in `recreated_*` go out first and are appended, as the server's dict did; a record that would change its type or its ends WITHOUT being named does not fit), folds the digest per entity and sets `diverged` on a mismatch or on a delta that does not fit; for the user's own commit it drops the committed batches and rewrites their temp ids in the rest (`remapOp`). The `(id, rev)` hash is the engine's own (`src/snapshot/`); the `entityHash` option replaces it, which is how tests hold it to another implementation. `verifyDigest()` recomputes the digest from every COMMITTED entity — the model's, with the committed image standing in wherever a staged batch has been — and sets `diverged` on a mismatch. Every operation returns a change set, whose `structural` says it may have moved more than properties: it names a relationship, a deleted element or an element absent when it began (presence is asked BEFORE a rebase rewinds, of the ids the staged batches and the change name), or it is an own commit with minted ids — a rebase over-reports what it touched, so a staged relationship makes any peer delta structural, which costs a refresh, never a stale tree. `stage(ops, {coalesce: true})` with ONE property update merges it into the first staged (never parked) op of the same kind and id — `{...old, ...new}`, later keys win, a `null` stays — as a new batch object under the old batch id: the op is first tried alone on top (a bad patch throws and cannot park the batch holding the earlier edits) and rewound, then the working copy rebases FROM that batch (the private `rebase` takes the index to start at; the batches below it stand). Never in place: an update bumps `rev` once per key and re-places a deleted key, so an in-place merge would leave a state no replay of `staged()` gives (key order and `rev`s included), which the seeded invariants hold. `adoptStaged(batches)` replays batches under their ids on a working copy with nothing staged or parked (a re-bootstrap carrying the user's edits), parks the refused ones and numbers the next batch past the highest id. A `duplicate` delta that comes with `own` naming a batch still staged or parked drops them all the same — the echo of a commit can arrive before its answer. `stagedVersion` moves whenever `staged()` or `conflicts()` come to hold other batch objects (a stage, a merge, a remap, a drop, a park; a plain rebase keeps them). `stagedDiff()` pairs each committed image with the record now, in first-touch order.
- **`src/snapshot/`** — `sha256` is FIPS 180-4 in plain TypeScript, synchronous because the digest fold cannot wait for WebCrypto; `entityHash(id, rev)` is CT-3's hash (the first 8 bytes over `utf8(id) ‖ 0x00 ‖ ascii(rev)`, the UTF-8 written by hand, a lone surrogate as U+FFFD), `modelDigest(model)` the port of `state_digest.model_digest`, and both are `WorkingCopy`'s default. `openSnapshot(chunks, metamodel, onProgress?, options?)` reads a `datarover.snapshot/v2` text from inflated bytes cut anywhere and returns `{header, workingCopy}` at the header's `rev` and `state_digest` — adopted, not checked: `verifyDigest()` is the check, whenever the caller chooses. Bytes are decoded by the host's `TextDecoder` (`fatal`, the byte order mark kept so that it fails the format check), reached through a typed `globalThis` lookup in `utf8.ts` because a declared global would collide with the host typings of any project that compiles these sources; `LineSplitter` cuts on LF alone; lines are parsed and loaded 500 at a time through `parseLines`, the first `elements` of them as elements, so the text is never held whole — 500 being the largest batch that stays a short step (at 2,000 the worst batch took 36 ms at M, _measured_). `options.pause` is asked after every loaded batch and every step of the index build (`rebuildIndexSteps`, reported through `options.onIndex`); only a returned promise is awaited, so an open with room left in its slice pays no microtask, and a throw ends the open. The pause sits in the batch loop, not the chunk loop, and a chunk is decoded in pieces of 64 KiB: a snapshot served from a cache arrives as a few large chunks, and awaiting a chunk that is already there resolves in microtasks, which is no yield to the host. Anything that does not start with `{"format":"datarover.snapshot/v2"` is refused at its first bytes. A refusal is a `SnapshotError`: the server's two texts (`snapshot v2 header carries no valid entity counts`, `snapshot v2 holds N entity lines, its header promises E + R` — the count is checked BEFORE the last lines are parsed, which is what gives a cut text the server's answer), the bulk loader's own, or the engine's for what the server's decoder never looks at (`rev`, `state_digest`, the ids, invalid UTF-8, a line that is not one JSON document, named by its number). Like the server's reader it takes a last line without its LF and CRLF line ends.
- **`src/steps/`** — a `Steps<T>` is a generator that cuts a long operation into steps of about a millisecond at M, each `yield` saying where it stands (`{done, total}`). Every long operation exists once, in that form, and its synchronous name drains it (`drain`): `IndexSet.rebuild` / `Model.rebuildIndexes` (`rebuildIndexSteps`, 1,024 entity visits a step), `WorkingCopy.verifyDigest` (`verifyDigestSteps`, 2,048 entities a step), `RootOrder.reset` — so no caller of the one-shot forms changed. A steps generator publishes nothing before its last step (`diverged`, the root order), so abandoning one leaves no trace; it holds iterators over the model across its yields, so the model must stay still between two of them, and each user says who keeps it still: the index build runs only while a replica is opening, a scan is protected by the service's queue, and the digest check is dropped and restarted after any transition. `sortedInSlices(items, compare, run = 2048)` is a stable bottom-up merge sort in steps (runs sorted natively, then merge passes into a second buffer, a step every `run` items written; the order `Array.prototype.sort` gives); it costs about twice the native sort and no step over 2 ms at M (_measured_), and serves the root sort of the index build and the hit sort of a search.
- **`src/read/`** — the read surfaces, a port of `routes/read.py` (and `routes/elements.py::get_element`) rule for rule. A read is `(model, placements, params)` → the route's HTTP response BODY, in pydantic's field order (`{id, type_name, properties, rev}`, `{items, total}`, …), as a plain call or a `Steps` generator; it reads the model and nothing else. `READS` maps the `lib/api` names (`getElement`, `getElementsBatch`, `listElementsPage`, `listElementRelationships`, `getModelSummary`) to them, and `readScans(method, params)` says which calls run in steps. `toWire` deep-copies a value into plain JSON-able data — a `PyFloat` as its number, a `bigint` as the nearest double, which is what a client's `JSON.parse` of the server's body gives — so nothing of the replica leaves; `readOps` reads ops as the server reads what a client sends: through `JSON.stringify` (an integral double is an `int`, `NaN` `null`, `-0` `0`) and the exact parser, then a shape check whose refusal is a 422 `ops[i]…` in the engine's words. `ViewPlacements` holds the element ids each loaded view places (an unknown, empty or absent view places nothing). An unknown element is the model's `ModelError` (`key`); page bounds (`limit` 1–500, `offset` ≥ 0) and parameter types refuse with `ReadError(422)` in the engine's own texts, because FastAPI, not the route, enforces them and no fixture can hold them — `too many ids: N (max 500)` is the route's own. `getModelSummary` answers `issue_counts: null` and `undo_depth: 0`, `model_rev` being the caller's. The tree (`tree.ts`: `getTreeItemsBatch`, `listContainmentRoots`, `listExcludedRoots`, `listContainmentChildren`): a child belongs to its FIRST containment parent (`parents[0]`, relationship order — a relationship restored under its old id goes last, so it does not win its child back), counts once however many parallel edges hold it, and levels sort by `(displayName, id)`, both by code point; roots come off the maintained root order, the excluded pool is that order minus the ids `ViewPlacements` holds for `view_id` (whatever a view places that is not a root changes nothing) with `total` counted over the whole walk. Search (`search.ts`, `listElementsPage` with a `q` that is not blank) is a full scan in steps — no trigram index (AD-13) — of `searchScore` over every element in state order, 512 a step: the query is `pyLower(pyStrip(q))`; a name (`nameOf`) is lowered with `pyLower` and scored by `nameScore` — exact 1000, prefix 100, word boundary 30, substring 10 — plus `len(query) / len(lowered name)` counted in code points of the LOWERED name (U+0130 lowers to two); the boundary test runs on the lowered name (U+212A lowers to `k`) as an occurrence walk that tries every start, overlapping ones included, which is what the route's regular expression does; then +5 / +2 for the id, +1 for the type (memoized per type), +0.5 per other string property (every `name`-cased key skipped). The additions happen in the route's order, in doubles, so equal scores are equal doubles and nothing is rounded. Hits sort by `(-score, id)`, ids by code point, through `sortedInSlices`; `total` is every hit; nothing is kept between pages (the server keeps nothing either).
- **`src/search/`** — a port of `core/search/criteria.py` and of `POST /model/search`. `readCriteria(raw, path)` reads the eight criterion shapes as pydantic reads canonical JSON: `type` required (a group holds leaves only), the defaults filled (`names`, `criteria`, `rel_types` to `[]`, a property's `value` to `""`, `datatype` to `null`), `relTypes` and `rel_types` both taken — the alias winning when both are given — unknown keys ignored, an absent key defaulted but a `null` taken only where the field allows one (`datatype`); what pydantic would coerce (`"3"` or `true` for a count) is a 422 `<path>[i].<key>: …` in the engine's words. `compileCriteria` translates every `matches` pattern, group members included, BEFORE any entity is matched: a pattern `translatePyRegex` answers `unsupported` refuses the whole call with 501 `reaches an unsupported pattern` (the shell then asks the server), one it answers `invalid` never matches, as `_safe_regex` has it. What the host cannot run although Python can is that same 501, mid-scan too, its detail never the source: a `RangeError` — a pattern nested past the translator's stack, or a subject past the backtracking stack of the translated `RegExp` (about 8M code units of `(a)*$`, fewer the more groups it holds) — and V8's `SyntaxError` `Regular expression too large` (a literal of 50,000 `k`, or 40,000 under `(?i)`), which V8 throws on a pattern's first run because it compiles lazily, apart for one-byte and two-byte subjects; `compileCriteria` therefore runs each translation once on `''` and on `'Ā'`, so that it refuses before the first step whatever the model holds. Nothing else is caught. `matchElement` / `matchRelationship` are the matchers line for line: text ops over `jsStr` of the value (missing and `null` are `""`), `contains` over `pyLower` of both and never splitting a surrogate pair (Python's `in` counts code points), numeric ops over `toNumber` — whose `PyOverflowError` for an int past the double range reaches the service as the route's 500 `int too large to convert to float` — with NaN on either side never matching; type names compare exactly (a subtype is not its parent) in `entity_type`, `rel_types`, `connected_to_type` and `endpoint_type`; a relationship count counts a self-loop once; an empty group matches; an element-only criterion on a relationship query, and the reverse, matches. `nameProp` is `name_prop`: a non-empty STRING only (never a list's first entry, unlike `nameOf`), `name` first, then every other `name`-cased key in property order. `searchModel` is the route body: `target` required, `criteria` default `[]`, `limit` 1–500 default 500, `offset` ≥ 0; every entity of the target in state order, criteria ANDed in order (an earlier one that fails keeps a later one from running, as `all()` does), 512 a step; the page is cut after matching and `total` counts every match; the body is `{target, elements, relationships, total}`, the other list empty.
- **`src/artifacts/`** — `ArtifactSet`, the project's artifacts in two layers: the committed ones the shell hands in (`setCommitted` replaces the layer, `put(changed, deletedIds)` upserts then removes) and over them the staged overlay mirrored from the frontend's buffer, one entry per id (`setStaged` replaces it). `resolve(id)` answers `{id, kind, name, payload}` or `null`: a staged `delete` hides the id, a staged `create` (under its temp id) is itself, a staged `update` lays its `name` / `payload` — whichever it carries — over the committed artifact and names nothing when none is under it, and otherwise the committed artifact answers; `size` counts the ids that resolve. `readArtifacts` (`WireArtifact`: `{id, kind, name, artifact_rev, payload}`, unknown keys ignored) and `readStagedArtifacts` (`WireStagedArtifact`: `{op: 'create', id, kind, name, payload}`, `{op: 'update', id, name?, payload?}`, `{op: 'delete', id}`) read a list as `readOps` does — `JSON.stringify`, then the exact parser, so a payload's `1` is an `int` and `1.5` a `PyFloat` — and refuse a malformed entry with a 422 `<where>[i].<key>: …` in the engine's words before anything moves. The set holds what the readers made, never what was handed in, and replaces entries rather than changing them, so a resolved payload stays as it was however the set moves after; it is read, never mutated. The service's set is not tied to a replica: it survives `close` and `open`, as the view placements do.
- **`src/navigation/`** — a port of `core/navigation` and of `POST .../artifacts/navigation/evaluate`. `readNavigation(raw, path)` reads a definition as pydantic reads canonical JSON: `kind` required on every definition, start and step, `op` on a set, the defaults filled (`direction` `out`, `types` / `target_types` / `criteria` / `steps` `[]`, `exclude_visited` `true`, a snippet `{}`), unknown keys ignored, criteria through `readCriteria`, and what pydantic checks but nothing uses checked all the same — `schema_version` an int on a path and a set, a path's `name` and every step's `comment` a string or `null` (a set has no `name`: pydantic ignores one), a `true`, `1.0` or `"3"` version refused where pydantic coerces it; the core's own texts where it has them (non-empty `children`, more than 10 steps, an operand without exactly one of `ref` / `definition`, a snippet with both), a 422 `<path>…: …` in the engine's words otherwise. A snippet is not read past its `ref` / `definition`: set or not is all that matters. `resolveRefs(defn, fetch)` inlines every operand's ref depth first — a ref already on the path is `RefCycleError` (`navigation reference cycle through 'x'`), a diamond is fine — and `navigationFetch(artifacts)` is the fetch the route uses: `ArtifactSet.resolve`, so a staged create, update or delete is what a ref sees, and anything but a `navigation` is `RefNotFoundError` (`unknown navigation artifact 'x'`). `navigationHasScript` is true when a script step with a snippet set is anywhere in the resolved tree. `evaluateSteps(mm, model, defn, limits, rowElements, meter?)` is `evaluate.py` line for line in steps: ids sorted by code point (`sortedInSlices` past 1,024), a hop's relationships counted once each (`either` counts a self-loop once) and charged to the budget before any is examined, parallel edges one continuation, a property hop through an element-typed property to the distinct STRING values naming an element (any other item, a dict or a list included, is skipped) and through a scalar one to a `PropertyValue` per scalar item in list order, a script step pruning (one with a snippet never gets here), a fresh budget per set operand, a truncated start set marking the path truncated. A `PropertyValue`'s `key` is `(type, value)`, so `True`, `1` and `1.0` stay three; `bigint` and `number` ints share one. `Meter` counts the units of a whole call — an edge or a property value examined, an element gathered, matched or expanded, a set member combined, a chain collected, an id sorted — and ends a step every 1,024; `evaluateNavigationCore` drains it. The core's `KeyError` (a filter or a property step on an id no element has) is `NavKeyError`, its `ValueError`s (`step_index`, an unbound row) `NavValueError`. `evaluateNavigation` is the route body: exactly one of `definition` / `artifact_id`, `row_element_id`, `limit` 1–500 default 100 and `offset` read first; then the refs resolved and a definition that reaches a script refused with 501 `reaches a script`, before every pattern of the resolved tree is translated inside `evaluateSteps` — so a definition holding both a script step and an unsupported pattern answers `reaches a script` — all before the first step; a page of `TreeItem`s and `{kind: 'value', value}` nodes (`toWire`), `{step_types, chains, total, truncated, warnings: []}`. Its error texts are the route's, quirks included (`C-22`): an unknown `artifact_id` is `unknown navigation artifact n1` without quotes; the evaluator's `KeyError`, which the route's `LookupError` handler catches, is `unknown navigation artifact 'x'`; an unknown row element with no steps reaches the page and is the 404 `x` of a raw `KeyError`.
- **`src/evaluate/`** — `EvalContext` (`{model, artifacts, placements}`, `artifacts` an `ArtifactSet`) and `EVALUATIONS`, the evaluations by `lib/api` name (`searchModel`, `evaluateNavigation`). An evaluation is always a `Steps` generator — the service runs it as a model-lane scan, whatever its params — and it reads its params, resolves its artifacts and translates its patterns before its first step, so a refusal (422, 501) happens before any work and leaves nothing behind.
- **`src/validation/`** — a port of the Python core's six built-in validators and of its scoped pipeline (`core/validation/`), held to `validation_kinds.json`. `Validators` holds them for one metamodel, in pipeline order — type conformance, multiplicity, facets, endpoint typing, containment, uniqueness — with their memos per type name, so one is built per metamodel and reused; `FacetPatterns` likewise. `validateScoped(model, ids, validators, patterns)` is `ValidationPipeline.validate(model, Scope(ids))`: each id once, its first occurrence deciding the order; an element through every element hook, a relationship through every relationship hook, an id naming nothing skipped; then every global hook, in validator order; `check` stamped with the validator's name. Only scoped runs exist: the full run (`Scope.all()`), which names ONE representative of a containment cycle, is not ported — a scoped run reports every scoped element whose first-parent chain reaches a cycle, those hanging below it included. Every issue is an error; a dangling reference, a second containment parent and a cycle are `structural`, the rest `conformance`. The messages are the core's texts: a value through `repr` (`pyReprValue`); a uniqueness identity through `repr` of the FROZEN value (`pyReprFrozen`: a list as a tuple, a dict as its key-sorted pairs, a missing key as `None`), rendered from the reported element's OWN key — `1`, `1.0` and `True` share a group — with its key relationships' endpoint ids sorted by code point, the group's primary being its member with the least `ord`; a facet bound is a float and renders as one (`5.0`) while the value goes through `str()` (`pyStrNumber`: `100000000000000000000`, `1e+20`); `max_length` counts code points; an enum member must be a string; a `date` is what `datetime.date.fromisoformat` accepts (`pyIsoDate`, CPython's parser over the UTF-8 bytes: `YYYY-MM-DD`, `YYYYMMDD`, `YYYY-Www[-D]`, `YYYYWww[D]`, ASCII digits, the calendar and ISO week 53 checked, and — since the parser never looks for the end — the two bytes past an eight-byte date not read at all, so `20240101xx` passes). Facet patterns are `re.fullmatch` through `translatePyRegex(…, 'fullmatch')`, each translated once and run on `''` and `'Ā'` when `FacetPatterns` is built: a pattern outside the translator's subset, or one the host cannot run (`beyondHost`, shared with the criteria), makes it `unusable`, and testing such a pattern throws `PatternUnusable` — the one way out, never a guessed answer. `wireIssue(i, origin)` is the routes' `IssueOut` (`{severity, message, target_ids, category, check, origin}`), `issueOwner` the first target, `issueKey` the multiset key `(severity, category, check, message, target_ids)`.
- **`src/service/`** — `Scheduler` (`scheduler.ts`) runs engine work on the host's thread in slices. One pump, two lanes, each in arrival order: the _control_ lane (the replica's own transitions) runs in any state and first; the _model_ lane runs while the scheduler is open. A job is a `read` (one call), a `transition` (one call that changes the model, never interrupted — a transition may run up to 100 ms, AD-23) or a `scan` (a `Steps` generator that `run()` makes). A transition waits for every read that arrived before it and holds everything behind it; at each slice boundary of a running scan, the reads queued before the first transition are answered and other scans are skipped over, never started — so a scan never sees the model move under its iterators (probe: a `Map` iterator that crosses a `clear()` and refill reads everything again, and `Model.elements()` does exactly that on the first ordered read after a rewind). `cancel(id)` removes a queued job or drops a running scan at its next step, unanswered; closed (`setOpen(false)`), the model lane keeps its jobs and a scan that was mid-flight goes back to the head to start over, `run()` called again. The pump reads the injected clock after every unit — a read, a transition, one step — and at `SLICE_TARGET_MS` (8, half of CN-3's 16 ms chunk: at M a collector pause of 5–8 ms lands inside a step now and then) calls `onSliceEnd`, awaits `yieldToHost()` and starts a new slice; messages are handled on those host turns only, never inside a unit. Idle and open, it gives the background task (`setBackground`) one slice at a time; `restartBackground()` drops its steps in flight (they published nothing) so a new run starts at the next idle slice. `pause()` lends the slice clock to work outside the pump (a snapshot open): `undefined` while the slice has room, else the host's turn. The pump starts on a microtask, so every job one message brings is queued before any runs.
  `createService(port, deps)` (`service.ts`) is the CT-4 dispatcher over one `Port` (`{post, onMessage}`: a `MessagePort` in a worker, `portPair()` in tests); `deps` is `HostDeps` plus `inflate`, since `src/` holds no timer, clock or gzip. A request `{id, method, params}` is answered `{id, ok, result | error: {status, detail}}` exactly once, or never once `{cancel: id}` came; a message without an id or a method is ignored. Errors: `OpError` / `ReadError` keep their status, a `ModelError` `key` is 404 with `errorDetail`'s quote-stripped text, `value` 422, a `SnapshotError` 422, an unknown method 404 `No method 'x'`, anything else 500 with its message. The replica is `opening`, `ready` or `diverged`. `open {project_id, metamodel}` discards any replica or open in flight (the heap never holds two) and starts `openSnapshot` over `deps.inflate` of a `ByteQueue` that `chunk {bytes}` feeds, with the scheduler's `pause` (which also stops a discarded open at its next batch); `end` answers the header once the replica is read and indexed — or the open's 422, which `chunk` and `end` then answer until the next `open`, a header of another project included — and the replica stays `opening`; `adoptStaged` (a control-lane transition) carries a re-bootstrap's staged batches over; `applyTail {text}` queues one transition per delta at once (control lane while opening, model lane after) and makes an opening replica `ready`, the scheduler open and the background digest check set; `applyDelta {text, own?}` is a model-lane transition, a 409 unless `ready`; `close` drops everything but the view placements, the artifacts and the queued model jobs. A delta or a tail crosses as the text the shell received and is read by `readDeltaText` / `readTailText` with the exact parser (AD-26: `JSON.parse` would lose `1.0` and integers past 2^53, which the digest cannot see); a commit response reads alike, `model_rev` standing for `rev`. Events: `replica {state, rev}`; `progress {task, done, total}` for `parse`, `index`, `tail`, `verify` — a task's first (`done` 0, which is how a restarted digest check shows) and last reports at once, the rest at most once a slice, from `onSliceEnd`; `changed {rev, staged_version, …ids, structural}` after every transition of a `ready` replica that changed something, which also restarts the digest check when an entity or the staged list moved. A delta whose digest disagrees, or a digest check that ends false, makes the replica `diverged`: the scheduler closes, so reads and edits posted meanwhile wait, and are answered from the replica the shell opens next (`close`, `open` … `end`, `adoptStaged` with what `staged` returned, `applyTail`). The method table (`METHODS`) is built from a few kinds, so the message handler has no per-method branch: `now` (answered at once, in any state — `open`, `chunk`, `close`, `staged`, `conflicts`, `setViewPlacement`, `dropViewPlacement`, and the artifact context: `setArtifacts {artifacts}`, `putArtifacts {changed, deleted_ids, staged?}` — the committed layer moves, then `staged`, when given, replaces the overlay — and `setStagedArtifacts {entries}`, each answering `null` and reading the whole call before the set moves), `later` (`end`), `read` (every `READS` name, a `scan` job when `readScans` says so; `getModelSummary` is handed the committed `rev` as `model_rev`), `evaluate` (every `EVALUATIONS` name, always a `scan` job over the ready model, the placements and the service's `ArtifactSet`), `inspect` (`stagedDiff`) and `transition` (`stage`, `unstage`: their params are read at arrival, so a malformed request is refused before it queues), plus the three replica methods above. Reads, `stagedDiff`, `stage` and `unstage` wait in the model lane for `ready`, so an edit made during a re-bootstrap lands after the adopted batches. `stage` reads its ops through `readOps` and always asks the working copy to coalesce; it answers `{batch, coalesced, changes, elements, relationships}`, the last two the post-state of what `changes` names as changed, both `null` past 500 entities. Every result and event is a copy built by the `wire*` functions — over a direct port pair nothing is cloned, and an uncopied result would hand out the replica's own property bags.
- **`bench/run.ts`** (`pixi run engine-bench`, input written once by `pixi run engine-bench-data` → `scripts/snapshot_v2.py`) measures model M in three passes: opening the snapshot against opening the same model as one document in the same pass, the digest check, the heap of one open replica, a 1,000-op batch staged and unstaged, a rebase of 100 staged batches, a delta — and the long operations driven step by step by hand (`stepped`), each with its total and its longest step: the index build (over the document model), the digest check, the broadest search (`q='a'`, hit sort included), a rare one, a criteria scan (`property name contains 'a'` over every element) and a navigation (an untyped scope, one `Owns` hop from every element, the sort of every id included). It measures STEPS, not slices: there is no scheduler in it; the browser benchmark below bounds the slices. It weighs the heap BEFORE it reads the document: the last text a regular expression ran over stays reachable in V8, and there that is 77 MB.
  **`frontend/bench/`** (`pixi run engine-bench-browser`, which builds the sandbox first) is the same model in the browser: a bench page on `http://127.0.0.1:5173` (`bench/vite.config.ts`: the app's COOP / COEP plugin, and `benchmarks/large.snapshot.v2.gz` — the encoder's own bytes, which `engine-bench-data` writes with `--gzip` — served at `/data/snapshot.gz` with its length and no `Content-Encoding`) drives the BUILT sandbox through `frame.ts` and `client.ts`, and `bench/run.ts` (Node's type stripping) drives the page through `window.bench` with Playwright's default headless shell, e2e's browser: three passes, each in a fresh context, medians, a verdict against CN-3, never a failing exit. It measures the cold open (first byte asked to `replica ready`, split at the last chunk sent, `end`, and when `parse` and `index` began and ended by the engine's `progress` events), the digest check, `stage` / `unstage` / `applyDelta` and the reads THROUGH THE PORT (round trips, so upper bounds), and the longest slice FROM OUTSIDE: a loop posts `staged` — a `now` method, answered on the worker's next host turn — each when the last was answered, so its longest round trip bounds the longest time the worker took no message, main thread included. The heap is the WORKER's: Chromium runs with `--remote-debugging-port`, the `worker` target of `/json/list` whose `url` holds `engine-worker` is reached over its own `webSocketDebuggerUrl` with Node's `WebSocket`, `HeapProfiler.collectGarbage` then `Runtime.getHeapUsage`, after the digest check is done (before, it is 15–35 MB higher); `backingStorageSize` is shown beside `usedSize`, not added. A worker has no `performance.memory`, and `context.newCDPSession(frame)` needs an out-of-process frame the headless shell does not give. The page cannot compute a state digest, so the last row's delta carries a wrong one and ends the replica — after the rewind, apply and replay it times.
- **`src/debug/`** — `dumpIndexes` (the canonical index dump the fixtures compare), `verifyConsistent` (incremental indexes against a rebuild, performed in place) and `shuffleAdjacency` (tests shuffle between steps to expose a dependence on adjacency order).
- **Golden fixtures** — `tests/golden/scenarios/*.py` run the real Python core and `pixi run golden-fixtures` writes `engine/fixtures/golden/*.json`; `engine/test/**/*.golden.test.ts` read them. The same task writes the generated sources `driver.GENERATED` lists: `lower-tables.ts`, `digit-tables.ts` and `regex-tables.ts` under `engine/src/value/` (`tests/golden/lower_tables.py`, `coerce_tables.py`, `regex_tables.py`). `tests/golden/test_fixtures_current.py` (part of `core-test`) fails when a committed fixture or one of those sources differs from what the core produces now. The Python core is the oracle: fix the engine, never the fixture. Values a plain JSON reader cannot hold are tagged (`tests/golden/tagged.py` ↔ `engine/test/golden/load.ts`). Model scenarios are step lists run by `tests/golden/model_steps.py` (`Recorder`): every step records its result or error text, the state digest and a fingerprint of the entity lines plus `tests/golden/index_dump.py`'s dump, and every n-th step carries both in full; `engine/test/golden/model-steps.ts` replays them, a second time with every uniqueness key forced into one bucket. A `batch` step runs an op batch through `routes/ops.py::_apply_batch` on the recorder's own model, as a session does — a refused batch must leave no trace, the recorder fails the run when one does, and `ops_refused` refuses after every kind of touch — and records the outcome, the first-touch before-images, the inverse ops and the delta a replica would be sent; `undo` runs an earlier batch's inverse ops in restore mode. A `read` step calls the real route function behind a `READS` or `EVALUATIONS` name on a `Session` built for the call, with EVERY argument passed (called directly, a route keeps its `Query(...)` objects as defaults; `searchModel`'s body goes through `SearchQueryIn.model_validate`), and records `model_dump(mode="json")`; the replay looks the method up in `READS`, then in `EVALUATIONS` (drained, over `{model, artifacts, placements}`), and compares `JSON.stringify` of both, values and key order at once. `artifacts` replaces the project artifacts a step may fetch (the replay's `ArtifactSet`, committed — or, in `staged.test.ts`, staged as creates under their own ids over an empty committed layer); `evaluateNavigation`'s route runs over a stand-in database session that serves them. `navigate` runs the core's evaluator itself with the step's limits and row binding, value nodes tagged, and `has_script` `navigation_has_script`, both on a definition whose refs resolve against those artifacts. `view` registers the element ids a view's nested folders place (`read._placed_element_ids`, the list the shell would register) and `drop_view` forgets them. `validate` runs `ValidationPipeline(default_validators())` over a scope — a list of ids, or `all_ids`: every element id in state order, then every relationship id — and records the issues as `IssueOut` bodies, which the replay compares as text with `validateScoped`'s. `insert_element` / `insert_relationship` put an entity in as committed state arrives (`Model.insert_element`), its type unchecked, so a scenario can hold a type its metamodel lacks. `engine/test/working/replica.golden.test.ts` feeds a `WorkingCopy` those deltas alone and expects the oracle's state, entity order included — through `ops_recreate` too (an entity created again under its id, unchanged in type and ends), which only the delta's `recreated_*` lists can express. `snapshot_v2` holds a snapshot text as the server encodes it, the texts no writer emits that the server reads alike (`same`) and the ones its decoder refuses in its own words (`refused`); `engine/test/snapshot/open.golden.test.ts` opens them all, cut into pieces as small as one byte. Every `observe()` of the golden runner computes its digest with the engine's own hash, so each fixture step holds it to `hashlib`.
